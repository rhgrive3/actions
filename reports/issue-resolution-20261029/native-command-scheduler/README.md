# Private multi-owner native command worker pipeline

Both #1665 and #1666 remain open. The production relay and NetMatch still accept owner-authored valid-shaped attack streams without mandatory trusted native action/contact simulation. This source-only slice connects the existing proposed `nc` command codec to the existing private native replay worker. It does not install or negotiate a production protocol, deploy a server, change existing actor/event tuples, or replace normal damage admission.

## Concrete integration and trust boundary

`attachTrustedNativeReplayWorker(port, session, {authorize, commandRoom})` now consumes `native-command-scheduler.mjs` when trusted host code explicitly supplies `commandRoom:{build,seed,at,dt,maxPendingFrames}`. The session must be a fresh actual private native replay at tick zero. Its native roster/lives, epoch and initial simulation time establish the scheduler's roster and source-time origin; the host selects fixed `dt`, common elapsed-budget origin `at` and bounded queue size. No received capability, snapshot, projectile or hit claim creates this configuration.

The worker accepts `enroll` with a capability, then `commands` with a packet containing the existing optional `nc` sibling. `authorize` supplies authenticated `from`, `epoch` and receiver-clock `at` out of band. An owner field inside JSON is never an authentication source. The scheduled worker rejects raw `advance`, so a caller cannot bypass the per-owner timeline and complete-roster barrier. The existing `claim` operation returns a committed, one-use native effect after checking scheduler consistency; it does not apply damage a second time. A client-owned worker remains client-owned and supplies no server trust.

Every packet's complete frame batch passes codec, owner/life, sequence, elapsed, fixed-dt, host-anchored source-time and queue-limit checks before prefix commit. A malformed final row cannot reserve its earlier valid rows or advance the peer sequence. Each owner must supply all of its actors every tick. Inputs wait in bounded per-owner queues until every roster owner has the same next tick; then the scheduler assembles canonical roster order and runs the actual native Actor/Runner/Physics/Projectiles and private effect owners once. Arrival order does not choose actor order. Exact envelope retries deduplicate without rerunning native updates.

Queue acceptance commits the entire accepted peer prefix **before native execution**. It is not an action/contact receipt or an execution transaction. If the second native tick in a batch fails, the earlier tick has run and the failing tick may have changed native state. The room permanently retires, clears queued prefixes and revokes all outstanding native effects; it neither rolls back nor retries that state. The same full replay clock/tick/closed/error/roster/life check runs immediately after each successful native step and before any claim. Reentrant scheduler and worker requests cannot enter the native scope or authorizer again.

## Delay, membership and lifecycle limits

Delayed other-owner packets can complete the barrier later within the bounded window, preserving the native result in the recorded CPU controls. Missing/disconnected actors do not receive fabricated neutral or held input. A trusted host must synchronously call the returned `endpoint.revokeOwner(owner)` on a trusted disconnect or authorization revocation. This retires the entire fixed-roster room, clears queued input and revokes contacts before another owner's packet can release the barrier. There is no received owner-drop operation. Unknown owners cannot revoke a room.

`revokeOwner` and scheduled `close` return `false` during synchronous native execution; callers must treat that as a failed operation and retry after the scope or fail closed. Normal MessageChannel dispatch is asynchronous. A synchronous custom-port request is rejected before authorization; an internal fatal close deferred by native execution is completed before any successful outer response can be delivered. Scheduled request IDs are positive safe integers used only for response correlation. The host must manage unique IDs for concurrent outstanding calls; native envelope sequence and one-use contact capabilities own replay admission. The default worker API retains its existing ordered IDs and raw complete-frame behavior.

Actual native life changes, unexpected roster/owner changes, out-of-band replay advancement and native faults retire this room. No reconnect, late-join, ownership migration, respawn checkpoint, missing-frame reconstruction or lag-compensated historical-world policy is invented. The production world driver, full input capture, canonical gameplay randomness/camera context, retained checkpoints and complete wire-effect mapping are still required before this pipeline could become a mandatory production authority. Real relay clients, all weapon/special modes and host/victim HP/stat/result agreement remain unverified by this slice.

## Validation

Node 22.23.4 source tests use the actual production-composed Actor, Runner, Physics, Projectiles and Boss combat methods with an explicit fixed display/muzzle seam, flat dry paint and fixed Boss state. A real MessageChannel carries independently authenticated A/B requests. Positive 30/60/120 Hz cases produce paid native shots, real flight/contact and HP effects; Boss and crablet controls reach their actual contact/damage owners. Opposite-owner delayed packet order yields exactly the same recorded native state and effects. No-input and covered shots produce no contact.

The focused suite also covers malformed batch tails, fixed-clock/first-time-origin/elapsed rejection without sequence poisoning, authenticated owner/epoch, backlog bounds, exact and modified retries, raw-advance bypass, RPC ID poisoning, trusted revocation with queued input and prior contact, faults inside a multi-frame batch, actual next-life transition, direct advancement before claim, final-tick caught disposal, authorization exceptions, synchronous reentry and old default worker compatibility. The receipt identifies exact final counts, hashes and commands; initial passing attempts are retained separately and not summed.

Comparison target remains Splatoon 3 Ver.11.3.0. This private authority integration introduces no retail weapon, movement, gear, damage, resource, geometry or timing parameter. It does not claim Nintendo network architecture equivalence or device/WAN/rendered validation. Physical-device validation is waived in the parent task.

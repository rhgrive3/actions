# Reject unexecutable native births before combat proof admission

Commit **f9585b37e3bd90442a3dda210e042f358a539fb3**, based on immutable2b01cd7e, closes a concrete malformed-projectile admission class. **#1665/#1666 remain open**: otherwise-valid forged owner action streams still authorize damage without trusted native action/contact authority.

## Reproduced production behavior and bounded change

The native `_tick` accepted projectile rows after only cosmetic validation and recorded them as combat proof. Native `_play` later rejected zero/invalid lifetime, nonfinite body fields or unsupported packet/unit layouts. A hit could spend the already-created proof even when the receiver created no projectile. An initial unchanged2b component probe showed36damage on native PvP/Boss/crablet HP with0receiver projectiles. The final31case regression file fails31/31 on that original adapter because invalid rows enter the actual native FIFO. These are admission failures, not fixture setup failures.

An additional18row fault probe derives a full current row from the installed native launch and `recProj` owners, alters only life0, straight=null or unit999, and uses the actual receiver/native HP methods. With only the FIFO gate controlled back to its former predicate, each fault deducts36HP on each of the three targets while unchanged native playback creates0projectiles. With the current gate, all nine corresponding rows retain HP, mint0proofs and enter0FIFO slots. Its setup is AST-extracted from the actual regression; the retained probe source and raw JSON distinguish this controlled old-admission comparison from the exact original-adapter31case run. It is not a browser/socket or trusted-contact proof.

The runtime now shares `validNetworkProjectileBirth` between native FIFO admission and playback. It reuses the existing lifetime/delay/cosmetic checks and finite fields5..18. FIFO admission also runs the existing pure `validFidelityRollerUnitPacket` parser, which validates the actual supported legacy/modern layout, unit and depletion marker. No new threshold or weapon formula is introduced. The parser clones the row and consults installed static definitions; it does not advance actor/resources/clock state. Dynamic preparation, ghost allocation and cosmetic capacity checks remain at their existing playback sites. A valid action is **not** rejected merely because cosmetic allocation is full.

Rejected rows are removed before native peer/sequence annotations, FIFO/staging and the receiver's private accepted-event commit. A mixed invalidseq2/validseq1 packet retains its valid birth and proof; later seq2 remains usable. Existing hit/Boss nonces, pending claims, life/ownership and contact policies remain. The native positive input rows in the55case single-round suite now come from the actual installed legacy launch or catalogue Runner and native serializer; the former11field synthetic birth was never playable. The missing-weapon regression deliberately projects a full produced row to the already-supported27field legacy layout, then nulls the local definition and asserts exactly one zero-use proof. It therefore still executes the missing-weapon policy rather than passing because timing rejection made the proof list empty. No assertion was relaxed.

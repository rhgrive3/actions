# #845 native ground cadence and rejected throttle

On source `2b01cd7efbca260a611165b1e3887ff48062ccd5`, a CPU-only native-floor probe shows that the issue's requested ground cadence is not yet met for this scenario. The actual loaded Player00 Character and NativePhysics two-triangle floor ran 240 warmup ticks and 600 further fixed 60 Hz ticks with the renderer-frame signal set to long-undrawn. All 600 ticks entered the offscreen budget; `_ground` and its Physics raycast occurred on every one. There were 3,707 of each, six or seven per tick. This is simulated time with a manual render-frame signal, not a 10-second live rendered match. The exact per-tick counting harness and raw results are [cadence probe](../845-cadence.mjs) and [log](845-cadence-latest.log.gz).

The original acceptance wording requires: “In a 10 s camera-away test, frustum-culled non-local actors no longer execute `Character._ground()` at simulation cadence” and “Long-offscreen actors show a material reduction in `Character.update/_buildPose/_applyPose/_updateHair` CPU time.” It does not require absolute zero calls or a whole-match speedup. The issue's possible fix direction suggests stopping visual foot-IK rays entirely, but that suggestion is not the stated cadence criterion. A previous report overstated it as a universal zero-ground-queries criterion. The previously reported 741 per 120 ticks counted `_ground` invocations, not distinct Physics raycasts; that aggregate alone did not prove per-tick cadence. The new per-tick result does so for this fixture. Physical-device traces are waived for this work.

A bounded alternate-tick omission of hidden `retarget.ground` is rejected. Three identical actual source-loaded actors were warmed and moved identically; two unchanged controls matched each other's muzzle exactly for 600 ticks. The mutant skipped the solver on 300 ticks and reduced ground calls from 3,693 to 1,889, but changed its live muzzle on the second tick, with maximum difference 0.003732003336725372 world units. The mutation exists only in the [probe](../845-throttle-control.mjs), not runtime. [Raw result](845-throttle-mutation.log.gz). It fails before re-entry and is not a candidate for integration.

The source ground solver feeds foot normals and target/filter state into pelvis lowering. `SourceMotion.applyBody` immediately feeds that pelvis correction into body balance; those transforms feed the live weapon muzzle. Existing offscreen code already cuts leg IK and decorative work after that pelvis dependency. A cross-tick exact-key analysis of the original 600-tick probe found 129 repeated keys out of 3,707, even with an unbounded set and before safe dynamic-terrain invalidation; it does not establish a material optimization or remove sampling at cadence. [Probe](../845-cacheability.mjs), [log](845-cacheability.log.gz).

Prior evidence includes a 10-second blockout browser camera-away test, first-visible render catch-up and 30/60/120 Hz image comparison. An older paired source-browser Character.update measurement was 0.590 versus 0.424 ms per call. The newer controlled 93.590/88.072 versus 53.373 ms comparison measures inclusive instrumented Actor._finishFrame/process CPU and is not isolated Character self time. These records support improvements but do not eliminate this native-ground cadence finding.

A future static-support certificate would need exact nearest-hit values for every required foot sample and guarded fallback for holes, stacked surfaces, moving support, changed owners and re-entry. It must not relabel per-tick terrain sampling as stopped work. No safe implementation is established by this experiment, so no runtime change or completion claim is made. Existing MOV-08b and Character holds remain.

Reproduce from the stated source with Node VM modules using each linked probe. [receipts.json](receipts.json) hashes the scripts and logs.

# #845: preserve native ground support between foot samples

The prior `flatFootHeightAt` shortcut treated three equal ankle/heel/ball height samples as a certificate for every point in their expanded rectangle. Three points do not establish the intervening native collision geometry. In an isolated source-loaded Actor fixture with actual NativeLevel triangle floor and NativePhysics, a static **dynamic-block entry** only 0.002 × 0.002 INKWAVE world units wide and 0.1 high fits between the sampled positions. The old shortcut substituted ground height 0; actual native `_ground` at that point returned `0.10000000000000003`. The block did not move during the measured interval. These are deliberately constructed INKWAVE coordinates, not Splatoon 3 Ver. 11.3.0 measurements or a claim about retail terrain.

The minimal fix returns null from the shortcut so the existing solver performs the actual native ground query. It retains the separately implemented exact within-update query memo. The source-only counterfactual reinstates the exact old helper in the same actual source fixture and checks a real contact-state difference at tick 5. On this fixture, recorded Actor position, velocity, HP and ink matched and the measured muzzle difference was zero; no broader gameplay equivalence or observed muzzle regression is claimed. For 120 measured fixed ticks, old/new `_ground` calls were **753 / 1002**; the witness support was queried **14 / 21** times. This is a correctness tradeoff, not a speedup or FPS measurement. Positive source traces of Actor state, muzzle and contacts matched across 30 / 60 / 120 Hz render schedules while using the same 60 Hz simulation ticks.

This fix **does not complete #845**. The earlier independently recorded `2b01cd7e` source-only native-floor 600-tick probe reported ground queries on **600/600** hidden budget ticks; see [the cadence report on the published #1911 head](https://github.com/rhgrive3/actions/blob/395b685df8c63da3de3e04c1f9ae1700d7dd1aa0/reports/issue-resolution-20261029/845-cadence/README.md). That number is a historical fixture result, not an exact measurement at this fix commit or a live 10-second browser result. A safe query reduction, required reentry verification and comparable visual CPU evidence remain; no physical-device validation is required for this task.

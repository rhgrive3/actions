# #725 original endpoint scope (2026-10-29)

**Disposition: bounded closure candidate after required current-head CI.** The original [issue #725](https://github.com/rhgrive3/actions/issues/725) reports the −5/+5 endpoint mismatch against an approximate public controller-bridge reference. Its fix direction allows interpolation if intermediate settings are unavailable; it does not require discovering Nintendo's unpublished complete transfer function. Physical-device testing was explicitly waived for this task. This conclusion does not establish exact retail parity or remove the uncertainty of the underlying reference.

The cited [bridge author's README](https://github.com/DamianS-eng/GTuner-TitanTwo/blob/main/README.md) describes a Steam Controller-to-Splatoon 3 setup and reports approximate lowest/default/highest ratios of 1:1, 1.8:1 and 3:1. It does not state a game update version, detailed measurement method or uncertainty. [Nintendo's controls guidance](https://www.nintendo.com/jp/games/feature/splatoonqa/other/gyro/index.html) confirms the presence and purpose of the motion sensitivity setting, not these ratios. Thus the bridge is the original issue's limited reference, not proof of an exact 11.3.0 curve. The October 10 follow-up comment explicitly identifies itself as generated by Claude Code and describes interim engineering work; it is not treated as a new user requirement.

| Original criterion | Existing result and limit |
| --- | --- |
| Lowest/default/highest gain | Composed `patches/splatoon3/adapter.mjs` installs device-degrees-per-360 anchors 360/200/120, giving gains 1/1.8/3. At −5 and +5 this resolves the originally reported 1.295/3.273 range. |
| Intermediate settings | Between these anchors, the code linearly interpolates **device degrees per in-game 360°**, not gain. For example −2.5 and +2.5 produce approximately 1.286 and 2.25. No intermediate value is claimed to be independently measured or exact S3. |
| Controlled rotation and cadence | The source endpoint suite and production-composed synthetic orientation suite pass **8/8**, covering 90°/s direct yaw, multiple above-filter rates, both axes, 30/60/120 Hz, irregular sensor times and lower-speed filter separation. |
| Other input ownership | Adjacent source suites pass **35/35**, covering world-orientation axes and screen rotations, raw-source handoff and dropout, stationary trust, sensitivity/inversion and a touch multiplier control. These are synthetic software tests. |

The direct arithmetic assertions use **absolute gain error < 1e−9** and the cadence comparisons use a 1e−9 numerical tolerance. These tolerances test implementation arithmetic; the bridge publication supplies no empirical accuracy bound, so they do not quantify reference measurement error. Existing `reference/curated-numbers.json` correctly leaves `camera.gyro.value` null and status unknown; this finding does not promote intermediate values or update that status.

## #890 distinction

The original [#890](https://github.com/rhgrive3/actions/issues/890) expressly requires the current-S3 hold cutoff/curve to have version-specific evidence before final tuning. Existing humanoid tap/hold behavior and 30/60/120 Hz source controls pass, but the project's 5F and 0.7 release factor remain explicitly provisional legacy-inspired values. The hardware waiver removes an instruction to perform device tests; it does not establish those original reference values. Keep #890 open for the original calibration requirement; do not describe the provisional constants as Nintendo values.

# INKWAVE ブキ挙動修正・検証報告 — 2026-10-09

## 結論と成果物の位置付け

作業元は `INKWAVE-main-5d0be6b7-{core,tools1,tools2,tools3}.zip`。ZIP内の識別情報が指定する基準は `5d0be6b7fdebfd07e696e75497aaa97aa5ff5648`。GitHubのclone・push・書込みは行っていない。四つのZIPを復元し、その内容をローカル基準としてコードを変更した。取得元ZIPのSHA-256は `input-archives.json` に記録している。

> **PR1188（Claude, 2026-10-09）で追加修正済み。** ブラスター床塗りの処理全体、スピナーのチャージ減速、ブラスター／ローラーのノックバック、シューター必要SP、キットのスロット単位整合、CPU/GPU本体輪郭、本番ビルドの予算を修正した。詳細は末尾「PR1188 完成作業」と [BLASTER_FLOOR_PAINT_COMPARISON.md](BLASTER_FLOOR_PAINT_COMPARISON.md)。以下の本文は元のオフライン作業の記録で、表A01〜A12は更新後の状態。

**実装・ビルド・ローカル回帰検証の成果物であり、「スプラトゥーン3 Ver.11.3.0との全差分を解消した完成版」ではない。** 特に、バレルのチャージ開始専用減速、ブラスターの爆風ノックバック、ローラーの接触ノックバック、マニューバー空中スライドの専用下降軌道、独自セット／スペシャルの置換は未完了である。これらを、単に「実機で未検証」の項目に紛れ込ませず、未実装修正として扱う。

測定スクリプトには別の古いコミットSHAが固定文字列で出力される不具合も見つかった。`SOURCE_IDENTITY.json` から入力基準を読み、実際の生成コードのハッシュとは別の来歴として記録するよう修正した。来歴がない場合は不明（null）、不正なSHAの場合はエラーとする。

この作業で新たに変更したのは、精度状態と実発射角の接続、ジャンプ後の精度回復、マニューバーの距離と空中入力受付、チャージャーの部分チャージ移動、これらを検証するテスト、およびオフライン診断ビルド・検証手順である。ローラー塗り境界など基準に既に入っていた修正は二重適用していない。

同梱するソースには元ZIP由来の全コード、追加コード、テスト、参照JSON、報告書を含める。変更していないフォント2ファイルは配布ZIPに含まない。元のcore ZIPから復元する `scripts/restore-original-font-assets.py` と、その2ファイルのハッシュを同梱する。元ソースへ変更ファイルZIPを上書きする方法では既存アセットをそのまま使用できる。詳しくは `REPRODUCE.md`。

## ビルドに使われる経路

`inkwave-public/` の原本は変更していない。`scripts/build-inkwave.mjs` が読み込むアダプター群によって、Actor、WeaponRunner、Projectiles、塗り、通信へ変更を組み込む。

主要経路は次の通り。

`Actor.update → WeaponRunner.update → 精度状態／チャージ・硬直状態 → Projectiles.fire* → spreadWeaponRound → 既存の弾道・衝突・ダメージ・CPU塗り → 発射時の値を記録した通信イベント → ghost再生`

新しい `runtime/weapon-accuracy.mjs` は `runtime/weapons.mjs` からインストールされる。設定値だけを追加して放置していない。乱数コンテキストは同期発射の間だけ保持し、例外／再入時も復元する。ネットワークの36列形式は変更せず、発射結果の既存記録経路を使う。遠隔側で未知の同一PRNGを再現したとはしない。

生成後の追加入力検査では、タッチ操作へ戻ったイベントでジャイロをリセットした後、次のController更新でさらにリセットして新しいセンサー差分まで消す不具合も再現した。イベントでのリセットに所有者と世代番号を記録し、そのイベント後の新しい差分をControllerが再破棄しないよう修正した。イベントを通さない所有者変更に対する古い差分の破棄は維持する。30/60/120Hzの更新、複数回の切替、通知されない切替の負対照を追加した。これはNintendoのセンサー仕様の変更ではなく、INKWAVE内部の二重処理の修正である。

HUDの `OUTER` 表示は `BIAS` に変更した。本家に同じHUDがあるという意味ではなく、INKWAVE診断表示が誤った確率解釈をユーザーへ示さないための変更である。

## ブキ別の変更と残る差

### シューター

**変更:** 射撃ごとの精度状態を実発射の角度生成へ渡す。以前の「外側の円錐か、0.45倍の内側円錐か」という二択を撤去。ジャンプの25F維持・70F復帰の端点と、その後の地上回復を経過時間で処理する。入力を離したかどうかではなく、最後の射撃からの回復待ちを使う。通常の6F連射とタップによる高速化防止は維持する。

**根拠／限界:** Biasの値・待ちフレームはS1。角度変換はS3の仮説から採用した校正。`q(u,b)=u^(log(b)/log(0.5))` は選択確率ではない。中央値・端点・乱数呼び出し数・再入安全性のテストを追加したが、50万標本の校正式検査を本家の50万発計測と呼ばない。水平／垂直の結合分布、反動、着弾の実機絶対寸法は未検証。

### マニューバー

**変更:** 通常連射に専用の精度状態を接続。通常Bias 0.01→0.25、専用回復量0.005、5Fの回復待ち、ジャンプ側のBiasと25→70F回復を扱う。汎用bloomによる追加の円錐拡大を外し、スライド後の集弾は既存のゼロ幅を維持する。

地上の移動本体は `rollDist=2.8` から `5.0` に修正。Actor側の地上限定ゲートを解除し、空中のスライド入力が既存のスライド状態機械へ届くようにした。壁登り中には受け付けない。4F始動・12F移動、7%の支払い、壁による停止、入力の一度だけの消費、低インク拒否、通常ジャンプとの二重実行防止を実Actorで検査した。

**残る差:** 距離全体を揃えただけで、`1-u²` の移動曲線や最速連続入力時の短縮、後続の滑り、塗り帯の時間形状は本家同定ではない。空中では入力を受け付けるようになったが、上下方向は依然として通常重力であり、専用の斜め急下降を実装していない。したがって空中スライドを完全再現としない。

### バレルスピナー

**変更:** 通常の拡散角を常時0.6倍に縮めていた処理を削除し、地上／空中の原典最大角と水平Bias 0.30、PitchBias 0.40を実発射へ渡す。汎用bloomを重ねない。ジャンプ側の角度復帰は端点を維持する。

**維持:** 二段チャージ、部分チャージ、20／40発の既存構成、空中・低インクの充填減速、インク予約・精算、キャンセルの専用経路は再実装していない。既存テストと生成コード測定で回帰確認する。

**残る差:** `VelGnd_Bias_Charge=.9`、`VelGnd_DownRt_Charge=.05` は抽出表に存在するが、専用の地上減速過程へ接続できていない。現行の汎用ブレーキが残る。水平／垂直の結合分布、弾速乱数の分布形、部分チャージ中間関数も実機一致未証明。

### チャージャー

**変更:** `charging` になった瞬間からフル時1.2に固定していた移動速度目標を廃止。開始側5.76からフル時1.2へ、`chargeT` に応じて目標を変える。開始1F、途中、フル直前、フル時、解除後の状態、ギア一度掛け、他ブキへの非波及を検査した。

**根拠／限界:** S5の開始・終端の参考値とS1のフル側値を区別して記録。直線補間は中間曲線の校正であり、本家から抽出した曲線ではない。最初のチャージ更新後は開始目標から既に少し下がる。目標速度とActorの加減速後の実速度を同一視しない。

**維持:** 最低8F射撃、有限飛翔、フル時貫通、75Fキープ、フル18%支払い、各種塗りの専用処理は既存実装を使用。ヒットスキャンから有限弾速へ今回新規変更した、とは記載しない。射程・ダメージ中間関数、装備／銃口位置、実機に対する照準表示はなお未検証。

### ローラー

**今回の実コード変更なし。** 旧台帳A09の帯幅／CPU所有の不一致は、基準のアダプターに修正が既に入っていることを確認した。初期調査で検討した二重の形状補正は撤回した。

横13発・縦5発の既存単位構造、減耗弾の衝突半径0.5、ドライローラー、衝突・塗り・通信の回帰を維持。GPU形状に関するCPU／シェーダーの論理検査は実行したが、WebGL2の実描画比較はこの環境では不成立だった。

**未実装:** 対人接触時の相互ノックバック。抽出された加速度や速度係数を、単位・適用時刻・被弾者の状態処理が不明なまま一発の速度加算に置き換えていない。塗り進みの速度・旋回・薄い境界、落下条件別塗りの実機忠実性も未検証。

### ブラスター

**変更:** シューターと共有する角度生成の二択を撤去し、Bias付き実発射へ変更。ジャンプ側はシューターの0.4を流用せず、ブラスター原典の0.5を使うテストとした。

**維持:** 9F後の制動、50F周期、発射前隙、直撃／時間起爆／地形接触、70→50ダメージ、遮蔽、壁落ち、バリア倍率など基準の専用経路を回帰確認。

### スロッシャー

**今回の実コード変更なし。** 4+5の単位構造、遅延生成、横振り追従、弾群重複ダメージ防止、着弾／中間塗り、高所時の縮小は既存の実装と検証を使用。古い「Biasを読まない」という指摘は採用しない。

## 検証方法と期待値の扱い

変更前のS3スイートを実行し、2,732件成功・失敗0・6件skipを記録した。最初の変更後全体検査は2,737件成功・3件失敗・6件skipだった。失敗を隠さず次の理由で見直した。

1. チャージ開始直後の最低速度固定を期待していたテストを、公開参考の開始端点・低下方向・フル時目標と、実Actor加減速の別々の検査へ変更した。途中の数値を実装から自動採用して本家の正解とする方法は使っていない。
2. 敵インク上のフルチャージ試験が、チャージャーで使わない別系統の `charge` のみを設定していた。チャージャーの `chargeT` を正しく設定した。敵インク係数の期待値は変更していない。
3. 旧二択／平方根円錐と追加乱数を前提とした角度テストを、明記した校正式の独立計算と乱数数・原点・姿勢・通信の検査へ変更した。これは校正式の実装検査であり、本家分布の実測検査に格上げしない。

入力の全体回帰でも、空中スライドを禁止し着地まで持ち越す旧前提が2件失敗した。空中入力は合法という公開仕様を根拠に、3入力方式での空中受付・着地での二重発動防止へ修正し、普通のジャンプの着地バッファと期限切れは別の正負対照で残した。該当ファイルは18件成功した。

射程・ダメージ・塗りの既存15条件goldenは変更していない。生JSON照合では7ファイル、明示63項目、数値ミラー1,045項目、プロファイル結線38項目を検査する。ただし全ミラーが全て実行時の同等処理へつながった証明ではない。検査JSONにも `mirrorIsNotProofOfRuntimeUse` を明記している。

30／60／120Hzの検査は、描画間隔を変えて同じ60Hz固定更新へ入力する比較と、精度の経過時間分割の比較を区別している。Nintendoの実機を30Hz／120Hzで測定したのではない。

15条件の数表は `MEASUREMENTS.md`。最終ログと終了コード、skip理由、初回失敗ログの位置は `TEST_RESULTS.md` と `test-results.json`。検査ZIPにはログと測定JSONを同梱する。

## ビルドとブラウザの制約

通常のesbuild最適化経路は維持したまま、`INKWAVE_BUILD_UNMINIFIED=1` を明示した時だけ非圧縮・非tree-shakingの診断ビルドを行う経路を追加した。同じアダプター／実行モジュールを使い、ハッシュ、アセット、サービスワーカーを生成する。

診断ビルドだけ、precache 12MiB・revision 24MiB・worker 128KiBへ予算を変更する。通常の5MiB・12MiB・64KiBの上限は変更していない。デフォルト経路のサイズ検査と診断経路の上限検査を両方追加／実行した。これは通常の配布性能検証を通した証拠ではない。この環境ではesbuildをDNS経由で取得できず、通常最適化ビルドは未検証。

生成コードのVM試験では、非圧縮コードに対応しないbootstrap正規表現、URL/import.meta不足、configの依存なしという古い仮定、受理済みassist一覧を渡さない旧イベントfixtureも修正した。ゲームの期待値を下げたのではなく、実際のモジュール依存とイベント契約を試験へ渡すようにした。生成後の追加132件は失敗0で通過している。

実ブラウザの既存HTTP検査は `ERR_BLOCKED_BY_ADMINISTRATOR` によりlocalhostへ移動できなかった。同じソース／生成コードのimport先だけをメモリURLへ対応付ける代替検査も作成・実行したが、実WebGL2コンテキストが取得できず失敗した。ブラウザポリシーの変更やソフトウェア模擬GLでの合格扱いは行っていない。

したがって、GPU対CPUの実画素一致、全アプリの描画、2ブラウザ接続、実端末の射撃感・音・操作遅延は未確認である。CPU論理検査・実行グラフ整合と別に扱う。

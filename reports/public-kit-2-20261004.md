# public-kit-2 — INKWAVE Splatoon 3 sub weapons (issue 177)

Lane: `freebuff-2`. Scope: owned files `patches/splatoon3/runtime/kit-subs.mjs`,
`patches/splatoon3/tests/kit-subs.test.mjs`, this report.
Reference version: **Splatoon 3 Ver. 11.3.0**.

## 1. What issue 177 actually is

The published runtime already has a working sub/special pipeline. The defect is
identity: `inkwave-public/src/config.js` gives every weapon `sub: 'bomb'`, and
`patches/splatoon3/runtime/install.mjs` never remaps it, so the Splatoon 3 patch
calibrates the main weapon while leaving the upstream generic Splat Bomb attached.

Lane 2 owns the **sub** half of that composition (Suction Bomb and Curling Bomb
behaviour). Per-main sub/special mapping, `specialCost`, menus/HUD, bots and
cross-lane wiring are parent-owned and are described in §6.

There is no `Actor._throwSub` in the published runtime. An earlier draft assumed
one; that was wrong and was corrected against the source.

**One list, one pass, one fuse decrement.** There is no second projectile list,
no second iteration over `this.bombs`, and no second fuse countdown. The kit
hooks are called from *inside* the native loop by the adapter
(`patches/splatoon3/adapter.mjs`, "sub weapon hooks"), and each one only supplies
values for the bomb already being processed.

### Adapter hooks (the only shared-file change in this lane)

Confined to `src/game/weapons.js`. The actor collision block and every unrelated
connection are untouched.

| --- | --- | --- |

Each hook receives the live `SUB` from `weapons.js` scope, so with
`installKitSubs` not applied the hooks resolve to `SUB.bomb` and behave exactly
like the unmodified native code. That is what keeps existing suites green.

## 4. Behaviour implemented (not labels)

**Suction Bomb — adhesion.** On a wall or ceiling contact the bomb enters
`stuck`, has its velocity zeroed, is offset along the contact normal by the same
`0.21` the native loop uses, and arms its fuse. A floor contact still arms
normally. The existing Splat Bomb arms only on near-vertical normals
(`hit.normal.y > 0.6`, `weapons.js:1310`); Suction is the reason those lines are
per-bomb rather than global.

**Suction Bomb — finite fuse.** The 11.3.0 table omits `BurstFrame` for Suction.
`fuse` stays `null` / `unknown-omitted`, and an explicitly labelled
`fuseFallback: 1.0` (`calibrated`, matching the existing INKWAVE bomb fuse) is
used so a stuck bomb still detonates. This is a functional calibration, **not** a
Nintendo figure, and is not presented as one.

**Curling Bomb — charge.** Holding scales `0 → 1` over the pinned `MaxChargeFrame`
window. Throw speed runs from `SpawnSpeedZSpecUp.Low` (24.0) at tap to the
explicit `SpawnSpeedZMaxCharge` (12.0) at full charge. The `SpawnSpeedZSpecUp`
Mid/High tiers (27.6 / 31.2) are the **gear** ladder and are deliberately not
used as the charge curve; they are retained on the spec for gear stacking only.

**Curling Bomb — blast tier.** `paintRadius`, `crossPaintRadius`, explosion
radius, both damage-band distances and the rolling trail radius interpolate
between `BlastParamMinCharge` and `BlastParamMaxCharge` by charge fraction.

**Curling Bomb — reflection, rolling, trail, burst.** A vertical contact reflects
the velocity with the pinned `ContactJumpPanel` rate and increments a bounce count
bounded by `MaxBoundNum = 3`. A floor contact settles the bomb, applies
`BaseSpeedComeOverRate`, starts the rolling state and arms the fuse. Each rolling
frame paints through the **real** `G.paint.splat` at the charge-scaled trail
radius and credits the owner via `addTurf`. When the fuse expires the step returns
`true` and the caller invokes the **native** `_explodeBomb` and removal path.

## 5. Honesty of the numbers

Fields the tables omit are never back-filled from another weapon and never
labelled `extracted`:

| Field | Value | Status |
| --- | --- | --- |
| `suction.fuse` | `null` | `unknown-omitted` (fallback `calibrated`) |
| `suction.inkCost` | `null` | `unknown-omitted`; resolved to the `calibrated` fallback `70` **before** the native ink check, so the release is actually charged |
| `suction.gravity` | `null` | `unknown-omitted` |
| `curling.chargeSpeedCurve` | `'linear'` | `calibrated` — tables give endpoints, not the curve |

`registerKitSubs` enforces this: if a profile supplies a value for an omitted
field, the matching `*Status` is rewritten to `calibrated` on the merged copy, and
the shared template is left clean so a re-registration re-derives identical state.
A test asserts exactly this.

   Until then the hooks resolve to `SUB.bomb` and behave natively.

   distinguish a Suction Bomb from a generic bomb. **Real multiplayer defect.**

## 6a. Review round 2 corrections

Defects found in review of `c3ffc7c`, each now covered by a regression that drives
the real native runtime.

| Defect | Correction |
| --- | --- |
| Release cost nothing | `kitSubRelease` returned `SUCTION.inkCost = null`, so `a.ink < bomb.inkCost` compared against null and charged 0. The effective cost is resolved before the native path and cached as `runner.s3Release`, one authoritative object consumed by both the ink check and the throw hook. |
| Gravity collapsed | Storm was dragged onto the bomb gravity and Curling ignored its own constants. Storm returns the native `24`; Curling uses `flyGravity` 57.6 in flight and `groundGravity` 5.76 while rolling; an untagged bomb keeps `SUB.bomb.gravity`. |
| Stuck bomb drifted | A stuck bomb kept receiving gravity and could detach without a physics hit. Gravity is `0` while stuck, so position is fixed while the single native fuse decrement continues. |
| Rolling penetrated the floor | Floor contact never clamped `b.pos`; it now clamps to `hit.point + 0.21` before settling velocity. |
| recBomb claim was false | The spec was attached from a wrapper that ran **after** the native `recBomb`, while the comment claimed before. The adapter now inserts `kitBombAttach` between the native push and the native `recBomb`; a stubbed `recBomb` asserts the record already carries its kit identity at snapshot time. |
| Direct contact damage unused | Implemented through the native `applyHit` using pinned `DamageDirectHit` (200 raw -> 20 HP) over `DamageDirectSpanSecond` (0.6667). |
| Charge-scaled fuse | **Not implemented.** 11.3.0 exports a flat `BurstFrame` (210F) and no field defines a charge-scaled fuse. Recorded as an open gap rather than invented. |

## 7. Verification — actual, not stand-in

Tests run the **actual adapted native modules** (`Actor`, `WeaponRunner`,
`Projectiles`, `Physics`, `PaintSystem`) in one VM, install the real production
installer, then apply `installKitSubs` exactly as the handoff does. Bomb records
are real `Projectiles.bombs` entries; flight, contact and fuse are the real
`_updateBombs`; detonation is the real `_explodeBomb`.

| Log | Result |
| --- | --- |
| `logs/kit-subs-prefix.log` | pre-fix FAIL, exit 1 |
| `logs/kit-subs-test.log` | **16/16 pass**, exit 0 |
| `logs/regression-own-file.log` | `bomb-motion` + `weapons` + `weapons-gear-flow` **27/27 pass**, exit 0 |

New this round, all against the real runtime: the native release charges suction
`70` from a 100 tank and refuses a 69 tank; storm gravity stays at the native
`24`; Curling uses `57.6` in flight and `5.76` while rolling; a stuck bomb holds
position across frames with no further physics hit while its fuse advances; a
rolling bomb is clamped to the floor surface; and the per-bomb spec is already
attached when `recBomb` snapshots the record.

Previously covered: composed release through native `throwBomb`,
real per-bomb spec attachment, free flight under per-bomb gravity, wall adhesion,
ceiling adhesion, counted fuse reaching zero and detonating into the native blast
with native list removal, rolling, **reflection after landing**, a bounded bounce
budget, the native `PaintSystem` accepting the trail centre, and no kit authority
for ghost bombs.

### What the tests do and do not prove

- `PaintSystem.splat` runs as the **real native method** in the trail test, so the
  Vector3 contract is genuinely exercised (`_rel.copy(center)` against a real face).
- Two transition tests use a **record-mode paint stub**, because the native
  density *write* needs the GPU atlas that only the `PaintSystem` constructor can
  build from a WebGL renderer, which this headless fixture cannot provide. The
  native blast, fuse and removal paths still run for real in those tests. This is
  stated rather than presented as full native paint coverage.

## 8. Limitations — explicitly unverified

1. **Not proven in a composed browser build.** `install.mjs` and the kit mapping
   are not wired; browser and exact-SHA Actions proof remain outstanding.
2. **Suction `fuse`, `inkCost` and `gravity` are omitted in 11.3.0** and remain
   `null` / `unknown-omitted`. The one functional fallback (fuse `1.0`, so a stuck
   bomb still detonates) is explicitly `calibrated`, not `extracted`.
3. **Curling charge->speed curve is linear by our reading**; the tables export
   endpoints only. Marked `calibrated`.
4. **Suction wall/ceiling adhesion is a functional calibration** — 11.3.0 exposes
   no adhesion field.
5. **No Switch, iPad or two-peer parity measurement** for sub throws, adhesion,
   charge timing or rolling trails.
6. **Remote sub identity is wrong** until `recBomb` carries the sub id (handoff 4).
7. **Native paint density writes are not covered** headlessly (see section 7).
8. `ChargeFrameBlastRate`, `BurstTimingSpeedStartRestFrame/StopBias`,
   `ContactDashPanel`, `KnockBackParam` degrees, geyser speed and
   `PaintBurstRadiusBias` are recorded in the spec but not yet driven by behaviour.
   A charge-scaled fuse is likewise an open gap.
9. **No renamed generic ability is claimed as a fixed Splatoon 3 kit.**

Parent integration review: direct-contact damage now spends the pinned 200 raw /10 =20 HP once per victim per DamageDirectSpanSecond, interpreted as a contact cooldown. The previous DPS reading was unsupported. The temporal interpretation and native bomb 0.2 contact expansion remain declared functional calibration.

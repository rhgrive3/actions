# public-kit-2 — INKWAVE Splatoon 3 sub weapons (issue 177)

Lane: `freebuff-2`. Scope: owned files `patches/splatoon3/runtime/kit-subs.mjs`,
`patches/splatoon3/tests/kit-subs.test.mjs`, this report.
Reference version: **Splatoon 3 Ver. 11.3.0**.

## 1. What issue 177 actually is

The published runtime already has a working sub/special pipeline. The defect is
identity: `inkwave-public/src/config.js` gives every weapon `sub: 'bomb'`, and
`patches/splatoon3/runtime/install.mjs` never remaps it, so the Splatoon 3 patch
calibrates the main weapon while leaving the upstream generic Splat Bomb attached.

Lane 2 owns the **sub** half of that composition (Suction Bomb and Curling Bomb
behaviour). Per-main sub/special mapping, `specialCost`, menus/HUD, bots and
cross-lane wiring are parent-owned and are described in §6.

**One list, one pass, one fuse decrement.** There is no second projectile list,
no second iteration over `this.bombs`, and no second fuse countdown. The kit
hooks are called from *inside* the native loop by the adapter
(`patches/splatoon3/adapter.mjs`, "sub weapon hooks"), and each one only supplies
values for the bomb already being processed.

## 4. Behaviour implemented (not labels)

**Suction Bomb — adhesion.** On a wall or ceiling contact the bomb enters
`stuck`, has its velocity zeroed, is offset along the contact normal by the same
`0.21` the native loop uses, and arms its fuse. A floor contact still arms
normally. The existing Splat Bomb arms only on near-vertical normals
(`hit.normal.y > 0.6`, `weapons.js:1310`); Suction is the reason those lines are
per-bomb rather than global.

**Suction Bomb — finite fuse.** The 11.3.0 table omits `BurstFrame` for Suction.
`fuse` stays `null` / `unknown-omitted`, and an explicitly labelled
`fuseFallback: 1.0` (`calibrated`, matching the existing INKWAVE bomb fuse) is
used so a stuck bomb still detonates. This is a functional calibration, **not** a
Nintendo figure, and is not presented as one.

**Curling Bomb — charge.** Holding scales `0 → 1` over the pinned `MaxChargeFrame`
window. Throw speed runs from `SpawnSpeedZSpecUp.Low` (24.0) at tap to the
explicit `SpawnSpeedZMaxCharge` (12.0) at full charge. The `SpawnSpeedZSpecUp`
Mid/High tiers (27.6 / 31.2) are the **gear** ladder and are deliberately not
used as the charge curve; they are retained on the spec for gear stacking only.

**Curling Bomb — blast tier.** `paintRadius`, `crossPaintRadius`, explosion
radius, both damage-band distances and the rolling trail radius interpolate
between `BlastParamMinCharge` and `BlastParamMaxCharge` by charge fraction.

**Curling Bomb — reflection, rolling, trail, burst.** A vertical contact reflects
the velocity with the pinned `ContactJumpPanel` rate and increments a bounce count
bounded by `MaxBoundNum = 3`. A floor contact settles the bomb, applies
`BaseSpeedComeOverRate`, starts the rolling state and arms the fuse. Each rolling
frame paints through the **real** `G.paint.splat` at the charge-scaled trail
radius and credits the owner via `addTurf`. When the fuse expires the step returns
`true` and the caller invokes the **native** `_explodeBomb` and removal path.

## 5. Honesty of the numbers

Fields the tables omit are never back-filled from another weapon and never
labelled `extracted`:

| Field | Value | Status |
| --- | --- | --- |
| `suction.fuse` | `null` | `unknown-omitted` (fallback `calibrated`) |
| `suction.inkCost` | `null` | `unknown-omitted`; resolved to the `calibrated` fallback `70` **before** the native ink check, so the release is actually charged |
| `suction.gravity` | `null` | `unknown-omitted` |
| `curling.chargeSpeedCurve` | `'linear'` | `calibrated` — tables give endpoints, not the curve |

`registerKitSubs` enforces this: if a profile supplies a value for an omitted
field, the matching `*Status` is rewritten to `calibrated` on the merged copy, and
the shared template is left clean so a re-registration re-derives identical state.
A test asserts exactly this.

## 9. cline-2 — the sub packet and the ghost it replays

Lane `cline-2`, 2026-10-04. Owned files unchanged from this lane:
`patches/splatoon3/runtime/kit-subs.mjs`, `patches/splatoon3/tests/kit-subs.test.mjs`,
plus the narrow sub-only `adapter.mjs` hook region in `src/game/weapons.js` and
`src/net/netmatch.js`. No native file, no `game/`, no other kit was touched.

### What was actually broken

The `'b'` event carried `b.kind` only. Every remote sub therefore replayed through
`ghostBomb` as the generic Splat Bomb: no identity, no charge, native gravity, a
bounce instead of adhesion, and the generic 1.0 s fuse. Three further concrete
defects sat behind that:

1. `ghostBomb` calls the native `throwBomb` **before** it sets `b.ghost`, so the
   `kitBombAttach` hook and `G.netm.recBomb` both run inside a window where the
   record is indistinguishable from an authoritative one. The only thing stopping
   the record was `!a.remote`, and `_adopt` clears that flag when a peer leaves.
2. The `Projectiles.prototype.throwBomb` wrapper consumed `s3SubHold` for every
   caller, including a ghost replay, clearing another owner's held charge.
3. `resolveSubForThrow` took `runner.s3Release.__charge` unconditionally, so a
   release cached for one sub could donate its charge to a throw of another.

### What changed

The packet gains two **appended** fields: `e[10]` sub id (`''` = generic) and
`e[11]` held charge 0..1. Both directions stay compatible: an older peer reads the
same native indices, and a newer peer reading an older packet sees `undefined` and
replays natively rather than inventing a spec.

Authority and presentation are now two resolvers. `resolvedOf` (unchanged,
`!b.ghost && b.s3Resolved`) still gates every selector that can paint, hurt, credit
turf or change a damage number. `presentedOf` is new and is read only by gravity,
contact, the fuse denominator and the visual burst radius — so a remote Suction Bomb
adheres and a remote Curling Bomb rolls and bursts on its own clock, while a ghost's
`s3Resolved` stays `undefined` for its whole life.

`withGhostBombSpawn()` brackets the native throw inside `ghostBomb`. Inside that
window `kitBombAttach` refuses to grant authority, `kitBombPacket` returns `null` so
`recBomb` records nothing, and the hold is not consumed. The counter is `finally`-scoped.

`resolveSubAtCharge` is split out of `resolveSubForThrow` so a ghost can resolve the
same object from a wire charge fraction instead of borrowing local held seconds.
Provenance labels are read from the module templates, not the live registry copies,
because `installGear` rewrites `sub.inkCost` on the live object for the length of one
update.

### Focused evidence

`node --experimental-vm-modules --test patches/splatoon3/tests/kit-subs.test.mjs`
— **27/27 pass**, exit 0. Log: `logs/cline2-kit-subs-subprotocol.log`.

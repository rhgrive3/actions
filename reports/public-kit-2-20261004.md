# public-kit-2 — INKWAVE Splatoon 3 sub weapons (issue 177)

Lane: `freebuff-2`. Scope: owned files `patches/splatoon3/runtime/kit-subs.mjs`,
`patches/splatoon3/tests/kit-subs.test.mjs`, this report.
Reference version: **Splatoon 3 Ver. 11.3.0**.

## 1. What issue 177 actually is

The published runtime already has a working sub/special pipeline. The defect is
identity: `inkwave-public/src/config.js` gives every weapon `sub: 'bomb'`, and
`patches/splatoon3/runtime/install.mjs` never remaps it, so the Splatoon 3 patch
calibrates the main weapon while leaving the upstream generic Splat Bomb attached.

Lane 2 owns the **sub** half of that composition (Suction Bomb and Curling Bomb
behaviour). Per-main sub/special mapping, `specialCost`, menus/HUD, bots and
cross-lane wiring are parent-owned and are described in §6.

This module therefore adds **no** second projectile list, collision pass, paint
pass, damage pass or bomb iteration. `stepSubBomb` is called once per bomb from
*inside* the native `_updateBombs` loop (parent-owned hook, §6).

## 4. Behaviour implemented (not labels)

**Suction Bomb — adhesion.** On a wall or ceiling contact the bomb enters
`stuck`, has its velocity zeroed, is offset along the contact normal by the same
`0.21` the native loop uses, and arms its fuse. A floor contact still arms
normally. The existing Splat Bomb arms only on near-vertical normals
(`hit.normal.y > 0.6`, `weapons.js:1310`); Suction is the reason those lines are
per-bomb rather than global.

**Suction Bomb — finite fuse.** The 11.3.0 table omits `BurstFrame` for Suction.
`fuse` stays `null` / `unknown-omitted`, and an explicitly labelled
`fuseFallback: 1.0` (`calibrated`, matching the existing INKWAVE bomb fuse) is
used so a stuck bomb still detonates. This is a functional calibration, **not** a
Nintendo figure, and is not presented as one.

**Curling Bomb — charge.** Holding scales `0 → 1` over the pinned `MaxChargeFrame`
window. Throw speed runs from `SpawnSpeedZSpecUp.Low` (24.0) at tap to the
explicit `SpawnSpeedZMaxCharge` (12.0) at full charge. The `SpawnSpeedZSpecUp`
Mid/High tiers (27.6 / 31.2) are the **gear** ladder and are deliberately not
used as the charge curve; they are retained on the spec for gear stacking only.

**Curling Bomb — blast tier.** `paintRadius`, `crossPaintRadius`, explosion
radius, both damage-band distances and the rolling trail radius interpolate
between `BlastParamMinCharge` and `BlastParamMaxCharge` by charge fraction.

**Curling Bomb — reflection, rolling, trail, burst.** A vertical contact reflects
the velocity with the pinned `ContactJumpPanel` rate and increments a bounce count
bounded by `MaxBoundNum = 3`. A floor contact settles the bomb, applies
`BaseSpeedComeOverRate`, starts the rolling state and arms the fuse. Each rolling
frame paints through the **real** `G.paint.splat` at the charge-scaled trail
radius and credits the owner via `addTurf`. When the fuse expires the step returns
`true` and the caller invokes the **native** `_explodeBomb` and removal path.

## 5. Honesty of the numbers

Fields the tables omit are never back-filled from another weapon and never
labelled `extracted`:

| Field | Value | Status |
| --- | --- | --- |
| `suction.fuse` | `null` | `unknown-omitted` (fallback `calibrated`) |
| `suction.inkCost` | `null` | `unknown-omitted` (fallback `calibrated`) |
| `suction.gravity` | `null` | `unknown-omitted` |
| `curling.chargeSpeedCurve` | `'linear'` | `calibrated` — tables give endpoints, not the curve |

`registerKitSubs` enforces this: if a profile supplies a value for an omitted
field, the matching `*Status` is rewritten to `calibrated` on the merged copy, and
the shared template is left clean so a re-registration re-derives identical state.
A test asserts exactly this.

## 6. Exact handoff to the parent

**Install** — add to `patches/splatoon3/runtime/install.mjs`, after
`installWeapons` and before `installWeapons`-dependent consumers:

```js
import { installKitSubs } from './kit-subs.mjs';
installKitSubs(api, profile);   // api already carries SUB, Projectiles, WeaponRunner
```

**Native hook 1 — per-weapon sub selection** in `WeaponRunner.update`, replacing
the hard-coded `const bomb = SUB.bomb`:

```js
const bomb = kitSubFor(a.weapon, SUB);
```

`installKitSubs` already wraps `WeaponRunner.reset` to refresh
`this.a.weaponRunner.s3Sub` and `this.s3SubHold`, so death and weapon change pick
up the new sub automatically. `gear.mjs` snapshots `SUB.bomb.inkCost` /
`throwSpeed` around the same call; the snapshot must widen to the selected sub
(parent-owned, noted in HANDOFF).

**Native hook 2 — per-bomb step** in `Projectiles._updateBombs`, inside the
existing `for` loop, after the native contact resolution and before the native
fuse block:

```js
const burst = b.s3Resolved && S3_SUB_BOMB_STEP(b, hit, dt, { paint: G.paint });
if (burst) { this._explodeBomb(b); this._releaseBomb(b); this.bombs.splice(i, 1); continue; }
```

`S3_SUB_BOMB_STEP` is exported on `api` by `installKitSubs`. No extra iteration
and no per-bomb allocation beyond fields on `b`.

**Native hook 3 — network.** `recBomb` packs `b.kind`. For remote clients to build
the correct sub mesh the packet must carry the sub id. `netmatch.js` is
parent-owned; the minimal change is to include `b.s3Sub?.id ?? 'bomb'` alongside
the existing `kind` field and have `ghostBomb` select on it. Ghost bombs remain
visual-only — the existing `nm.mute` guard already prevents remote paint and
damage, and this module does not weaken it.

**Kit mapping for the acceptance criteria** (parent owns; `profile.json` is not
edited by this lane):

| Main weapon | `sub` | `special` | base PFS |
| --- | --- | --- | --- |
| `shooter` (Splattershot) | `suction` | Trizooka | 200 |
| `roller` (Splat Roller) | `curling` | Big Bubbler | 180 |
| `charger` (Splat Charger) | `bomb` | Ink Vac | 190 |

`charger` correctly keeps the real Splat Bomb; `suction` and `curling` are not
renamed stand-ins for it.

## 8. Limitations — explicitly unverified

1. **Not yet in a composed browser build.** Until the parent wires §6, the module
   is exercised against native-shaped fixtures, not the installed composition.
   Browser proof remains outstanding.
2. **Suction fuse, ink cost and gravity are unverified**, per §5.
3. **Curling charge→speed curve** is linear by our reading; the tables give
   endpoints only.
4. **Suction adhesion is a functional calibration.** The 11.3.0 tables expose no
   adhesion field; wall/ceiling sticking is implemented from observed behaviour,
   not an exported parameter.
5. **No Switch, iPad or two-peer parity measurement** for sub throws, adhesion,
   charge timing or rolling trails. All numbers above are extracted or calibrated,
   none are device-verified.
6. **`Curling.chargeFrameBlastRate`, `DamageDirectSpanSecond`, `KnockBackParam`
   degrees, `ContactDashPanel`, geyser speed, `PaintBurstRadiusBias`** are
   recorded in the spec but not yet driven by behaviour.
7. **Remote/ghost sub identity** needs the §6 hook 3 packet change to be correct
   in a real match; until then a remote Suction Bomb renders as a generic bomb.
8. **`Special Charge Up` / `Sub Power Up` gear** interaction is parent-owned; the
   gear snapshot must widen from `SUB.bomb` to the selected sub or modifiers will
   apply to the wrong entry.

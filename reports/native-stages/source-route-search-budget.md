# Bounded native route search

Ordinary native source stages now use the existing finite `max(6000, nav.nodes.length * 4)` route-search bound. Previously, only stages opting into source climb/drop/Surge received that bound: the original Wahoo pad `[-85,18,0]` could not select its real 118-node route to the existing zone center with 6,000 search iterations. The installed production `BotBrain._pathTo` now selects that route without enabling traversal flags. Legacy blockouts still pass `undefined` to retain the existing 6,000 default.

The runtime change is one adapter condition, `G.level.native`. It changes no source geometry, polygon mask, graph edge, stage definition, opposing pad, Tower placement, traversal flag, Surge behavior or goal-selection policy. Wahoo's pinned KiTrix `Vss_Carousel03` OBJ remains SHA256 `0d9fc1e01e59c34301d65e8d2a8bf2aa90e0f4920f63daf4ac567df0c4ba33db`, at repository commit `0611f51b35c9736ee986fb2218461e2585b7875e`. The original graph has 12,645 nodes, 8,369 valid nodes and a finite 50,580 bound. Forbidden opposing native spawn targets remain rejected; real Tidewater path selection and its default argument remain unchanged.

Old 6,000 returns null at all rates and the installed method returns the same 118-node source route.

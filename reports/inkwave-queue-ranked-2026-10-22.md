# Library queue: ranked rules, native BOT support and Boss navigation

Baseline: `c0938a3f84768474df91713f7b372f9d7f8fe96a` (main, 2026-10-22).
Reference behavior remains the existing Splatoon 3 Ver. 11.3.0 implementation. No weapon, timing, score, movement or collision constants are intentionally changed. This report records code/logic evidence; it does not certify retail hardware parity, browser frame time or iPad performance.

## Implemented changes

- BOT/Boss plans reuse winner-position vectors, lazily share the invariant retreat distance, reuse exact owned-node nearest results with original duplicate-coordinate tie order, and share refill distance within each synchronous input branch. Existing PR #1781's unchanged aim-wander expression is incorporated.
- Boss perception retains a current crab target, ranks active shapes with one exact distance calculation per shape, clears reusable record references even on failure, and does not repeat an already successful LOS observation. Flank LOS uses the proven +3 upper bound. Evade heading/trig and BossNav cast headings are calculated once without approximation.
- Native navigation uses independent caller-owned ray results, static cardinal tuples, local spatial cells for spawn candidates with original node-order sorting, and a graph-owned stamped BFS workspace. Directed reachability, enemy spawn restrictions, IDs/order and the existing per-brain start-node candidate-cache behavior remain intact. Foot, climb, boarding and ranked-goal probes reuse vectors/results under their existing actor/brain ownership.
- Ranked catch-up intervals create their disarmed input view once per update. Frame rows, input rows and callback closures are owned by the match. Non-zone rules reuse immutable zero-coverage values. The host pose/owner/life/session admission and edge-consumption order remain unchanged.
- Rainmaker barrier aggregation uses two scalar lanes; nearest pickup and checkpoint selection are linear with their original ties. Static checkpoint count geometry is precomputed. Grounded last-position and normalized idle-charge state avoid repeat allocation. Shot sphere tests use the identical reduction order without per-victim arrays. Terminal blast origins are only created when needed. Shot geometry is effects-owned and active materials are reference-counted by exact RGB values, preserving palette precision and disposal.
- Clam timer transition collections are lazy. Actor filtering is scoped to one synchronous rule update, pickup snapshots use nesting-safe reusable arrays, and projectile/aging passes preserve the original fixed snapshot membership while avoiding copies where removals rebind the field array. Projectile catch admission shares its exact body center. Held-power tests are coalesced within the same mutation-free phase. A nearest-clam fast path retains the full sorted fallback. All 211 throw-angle samples are evaluated exactly at module setup.
- Rainmaker shield approach candidates use a stable min-heap. Tower approach skips A* only when a zero route-cost lower bound cannot beat an existing result, after checking every edge cost is finite/nonnegative within that synchronous selection; negative/custom graphs retain the old search cadence.
- Tower rail lengths/bearings are precomputed in the original arithmetic order. Stationary transforms skip AABB/matrix/paint-geometry rebuilds while rider handling continues. Count memoization verifies actual canonical engine methods, all count inputs, checkpoint contents, external count/leader changes, overtime, restore/reset and non-finite fallbacks; custom setCount overrides retain their repeat-call side effects.
- World clam markers retain unchanged resources, world input vectors are read without needless copies, zone colors update only on a color transition, and zone cells store scalar grid coordinates. The internal `center` inspection accessor remains available without a persistent Vector3 per cell. Zone coverage caches only versioned paint with matching grid and cell-index identity; unversioned/custom paint still rescans. Production clear, splat and owner-replay writers advance paint.version.
- Ranked HUD caches nodes per root and avoids unchanged text, color, visibility and leading-class writes.
- Guest snapshot admission validates once at `RankedEngine.restore`, retains its malformed/old-state rejection and atomic candidate swap, and avoids redundant clone/seed work during received Clams restore. Public standalone rule restore/snapshot behavior stays detached.

## Structural follow-up disposition

- Native graph construction now uses the proposed main-thread time-sliced fallback. The synchronous and asynchronous APIs consume the same ordered generator. The awaited detached graph is published only when complete/current, and cancellation releases a pending animation-frame wait without requiring a rendered frame. Build metrics expose elapsed time, measured maximum slice and yield count. Cells/edge candidates are scheduling boundaries; a single source transition remains atomic, so the 4 ms budget is a scheduling target rather than a hard longest-task guarantee. No real source-stage/device latency acceptance is claimed.
- The broad proposal to skip ordinary ranked planning/steering is rejected by executable actual-source counterexamples: it changes retained jump input, special activation and random draw order. A safe canonical NavGraph memo now shares only identical endpoint/team/iteration searches inside one synchronous ranked update, returns independent arrays, bypasses callback-qualified/custom paths and clears in finally. A 300-tick actual BotBrain comparison preserves route, timers, RNG, action, spring and progress state while avoiding repeated identical searches. Different-goal base searches and both stateful steers are deliberately preserved.
- Zone capture's redundant batch scope/helper was removed after combined-tree measurements showed that native owner's `Level.queryFaceBlock` already bypasses broadphase in O(1) for every static restricted face (commit `42cefa790b7133226c1a92bd9950019db94e6b5b`). That owner applies to legacy and native layouts. The queue is a duplicate of that integrated repair. Every canonical per-cell CPU/GPU/network stamp remains unchanged. The regression uses an explicit before-face-optimization control (`queryFaceBlock` returns null), preserves all recording/grid/quad comparisons and requires zero production hash reads. No network compression or actual-device timing is claimed.

The three structural items are now disposed: one implementation, one duplicate of the native direct-face repair, and one safe subset plus counterexample-backed rejection of its unsafe broad proposal. The ledger explicitly records those limits rather than claiming removed behavior. Optional native source assets, real GPU/device acceptance, long-session memory and performance measurements remain unavailable/unperformed.

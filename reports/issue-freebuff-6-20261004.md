## 180 — Squid Surge charge-and-release wall motion

- **Status: resolved at baseline; proven against the composed Actor.**
- **Splatoon 3**: hold jump while swimming up an own-ink wall to charge, release
  to launch upward; charge length scales the launch up to a cap (Inkipedia
  Mobility). Exact Nintendo frame counts/velocities are not asserted here.
- **INKWAVE public composition**: `patches/splatoon3/runtime/movement.mjs`
  (`beforeActions`) already owns the `squid`-form wall Surge: `phase: 'charge'`
  accumulating `dt / cfg.surge.chargeTime`, then `phase: 'burst'` on release
  with `speed = minimumVelocity + (velocity - minimumVelocity) * charge`.
  `profile.movement.surge` supplies `chargeTime 0.75` (pinned to
  `WallJumpChargeFrm_Low = 45`), plus duration/velocity/armor. The adapter
  changes the native jump guard to skip the Surge-consumed press
  (`!actionHandled && ...`) and calls `beforeActions` after `_updateClimb`.
  Presentation is in `movement-motion.mjs` / `wall-motion.mjs`.
- **Reproduction (composed)**: own-ink wall, squid form, hold jump → charge with
  `vel == 0` and no detach; release → `vel.y > 0`; dry/enemy-ink wall → no
  charge. Covered by
  `patches/splatoon3/tests/public-issues-6.test.mjs` (4 tests) and the existing
  `integration.test.mjs` / `movement-motion.test.mjs` / `wall-motion.test.mjs`.
- **Verified**: charge state, still body, remote-readable
  `s3.actions.surge === s3.surge`, `anim.surgeCharge` fraction, monotonic launch
  to the cap, dry/enemy/unclimbable rejection, ordinary climb retained.
- **Unverified / limitation**: `movement.surge.velocity`, `duration`,
  `armorTime`, `armorHP` are marked "calibration or derived value" in
  `numeric-status.json` (no binding); they are not confirmed Nintendo values.

## 86 — Super Jump ignores profile and Quick Super Jump timing

- **Status: resolved at baseline; proven against the composed Actor.**
- **Splatoon 3 / pinned reference**: preparation `SuperJump_ChargeFrm = 80F`
  (1.3333 s), travel `SuperJump_MoveFrm = 138F` (2.300 s); Quick Super Jump
  shortens both (Inkipedia Quick Super Jump).
- **INKWAVE public composition**: `patches/splatoon3/runtime/gear.mjs` sets
  actor-local `s3.jumpChargeTime = superJump.chargeTime * quickSuperJump` and
  `s3.jumpFlightTime = superJump.flightTime * jumpFlightTimeCurve`. The adapter
  replaces the old hard-coded `s.t > 0.75` threshold with
  `s.t + 1e-10 >= this.s3.jumpChargeTime` and the distance-derived
  `1.15 + min(0.6, d/80)` duration with `s.dur = this.s3.jumpFlightTime`.
- **Verified (composed, AP0)**: charge → flight at exactly 80 ticks, flight
  `dur === 2.3`, landing after exactly 138 ticks. With max Quick Super Jump the
  charge transition and flight duration both shorten according to the profile
  curves, so gear AP reaches gameplay (not only the stored value).
- **Unverified / limitation**: the ~21F extra preparation for a humanoid-form
  start is **not** implemented. Inkipedia cites it but the repository has no
  pinned/verified parameter for it, so per AGENTS it is left explicit rather
  than guessed. `superJump()` still normalizes the starting form to `squid`.
- **Not changed**: presentation layer (`superjump-motion.mjs`) already reads the
  same actor-local timing; separate tests cover it.

## 91 — Published runtime used the 5.5 s out-of-bounds timing for normal splats

- **Status: fixed.**
- **Report / reference (secondary)**: ordinary player-caused splat ≈ 8.5 s,
  drowning ≈ 7.0 s, out-of-bounds fall ≈ 5.5 s (Inkipedia Quick Respawn, as
  cited by the issue). The repository's own `reference/curated-numbers.json`
  records `respawn.total` as **unknown** ("only component gear curves are
  available"), so these totals are recorded as the report's secondary values,
  not official 11.3.0 data.
- **INKWAVE before**: `inkwave-public/src/config.js` `PLAYER.respawnTime = 5.5`
  and `Actor.splat()` unconditionally `this.respawnTimer = PLAYER.respawnTime;`,
  so every death used the 5.5 s out-of-bounds base. `profile.player` did not
  override it.
- **Fix**: `profile.player.respawnTime = 8.5` (normal) and a new
  `profile.respawn { normal: 8.5, water: 7.0, outOfBounds: 5.5 }`. The adapter
  replaces the native assignment with `setRespawnTimer(this, cause)`
  (`resources.mjs`), selecting the base by cause. Quick Respawn
  (`gear.mjs`) now subtracts from the corrected normal base.
- **Reproduction (composed)**: `a.splat(null)` → `respawnTimer === 8.5`;
  `a.splat(null, 'water')` → `7.0`; max Quick Respawn shortens from 8.5.
  Covered in `public-issues-6.test.mjs`.
- **Fail-closed**: changing the native assignment makes `adaptSource` throw
  (`death-cause respawn timing`), so the composition cannot silently revert.
- **Unverified / limitation**: the 8.5/7.0/5.5 totals are Inkipedia-sourced and
  not confirmed against official 11.3.0 parameter data. Fine-grained Splatoon 3
  phases (splat animation vs splat cam vs respawn animation) are not modeled.
  The remote/network path `net/netmatch.js::_remoteSplat` still uses the single
  `PLAYER.respawnTime` (now 8.5) without cause routing; local `Actor` cause
  routing is what is regression-verified here.

## 76 — Activating a special does not refill the ink tank

- **Status: fixed.**
- **Splatoon 3**: successful special activation immediately refills the ink tank
  (Inkipedia Special weapon / Ink tank).
- **INKWAVE before**: `Actor._startSpecial()` set `this.special = 0` and started
  `slam`/`storm` but never restored `this.ink`.
- **Fix**: `installResources` wraps `Actor.prototype._startSpecial`; on a
  successful transition (native sets `specialActive`) it sets
  `this.ink = PLAYER.inkMax` exactly once and emits `special:refill`.
- **Reproduction (composed)**: at `ink = 8`, activation → `ink === 100` for both
  `slam` and `storm`; a not-ready input does not refill; staying inside the
  active special does not refill again; the next shot consumes normally.
  Covered in `public-issues-6.test.mjs`.
- **Unchanged**: special gauge consumption (`special = 0`), `stats.specials`,
  and the existing recovery-suppression timing.

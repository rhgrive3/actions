# 状態専用の更新経路が共有フェーズを飛ばす問題 (#744 / #707、#728 は再現せず)

基準: `main` `37ab02fcb7314eee8a6b3e6e8e6b0593610e7bff`。本家参照は Splatoon 3 Ver.11.3.0。`inkwave-public/` は無変更で、`patches/splatoon3/` のビルド時アダプタとランタイムだけを変更する。

共通の原因: 特定の状態・所有形態（スーパージャンプ中、オフライン一時停止中）が通常の `Actor.update()` 後半や通常のゲーム時間の進め方とは別の経路を通り、通常経路だけが持つ共有処理（リソース処理、ゲーム時間の停止）を実行しない。修正は各状態に処理を複製せず、既存の共有関数を同じ規則で 1 回だけ呼ぶ。

## #744 スーパージャンプのチャージ中に敵インクのダメージが止まる

| 項目 | 内容 |
| --- | --- |
| 本家の根拠 | 被弾の扱いは #255 の整理（チャージ中は被弾する、無敵は飛行中のみ）に従う。チャージ中も敵インク上で継続ダメージを受けるかのフレーム単位の実測資料は未確認。INKWAVE 内ではチャージ中に通常の武器ダメージを受け付けているため、敵インクだけが止まるのは内部矛盾 |
| INKWAVE の実装箇所 | `patches/splatoon3/adapter.mjs`（`super jump charge resource phase`）。`Actor.update()` のスーパージャンプ分岐が `updateResources()` より前に `return` していた。tick 開始時の phase が `charge` のときだけ、同じ `updateResources(this, dt)` を 1 回実行する。`flight` は従来どおり実行しない |
| 再現操作 | 敵インクの床でスーパージャンプを開始し、80F のチャージ中の `hp` / `damageFromInk` / `s3.enemyInkTime` を見る。修正前は全く変化しない |
| プレイへの影響 | 0 AP で最大 24 HP（上限 40 HP の範囲内）の継続ダメージが消えていた。修正後は同じ床に立ち続けた通常 Actor と同じ値になる |
| 付随する変化 | 共有フェーズのため、チャージ中のインク回復・HP 自然回復・敵インク蓄積の減衰も通常規則で進む。本家でチャージ中にこれらが進むかの実機計測は**未確認** |
| 確認状態 | ロジック確認済み（実 Actor / Physics / Level、60 Hz、30/60/120 Hz 一致）。本家実機比較は未確認。飛行中の敵インク蓄積値は飛行前の値を保持したまま（飛行中に地上判定が無いためリセットもされない）で、着地直後の猶予の扱いは本家との比較が未確認 |

## #707 オフライン一時停止中に Roller の接触ダメージ待ち時間が進む

| 項目 | 内容 |
| --- | --- |
| 本家の根拠 | 本家のオンライン対戦には一時停止が無い。INKWAVE のオフライン一時停止は Match・弾・アクターを凍結する設計で、ゲーム時間 `G.time` だけが進むのは内部矛盾 |
| INKWAVE の実装箇所 | `patches/splatoon3/runtime/clock.mjs`。固定 60 Hz の tick で、`match.paused && !match.attract` の間は `G.time` を進めない。オンラインの一時停止は `paused` を立てない（`main.js` `pause()`）ため従来どおり進む |
| 再現操作 | オフラインのボス戦で Roller の接触ヒット直後に一時停止し、0.5 秒以上待って再開する。修正前は再開直後の tick で次の接触ヒットが通る |
| 同じ原因の他の箇所 | `G.time` を基準にしていた Roller drop の Boss 0.3 秒グループ、Flow のアシスト有効時間（`runtime/flow.mjs`）、イカ/ヒト切替の音の間隔も同様に一時停止中に進まなくなる |
| プレイへの影響 | 一時停止の長さ（0.1 秒/1 秒/10 秒）で再開後のダメージ・アシスト判定が変わらない。一時停止中は既存の idle アダプタが静止画を表示するため、`G.time` を使う水面等の表示も見た目上は変わらない |
| 確認状態 | ロジック確認済み（30/60/120 Hz、0.1/1/10 秒）。ブラウザ実動作での Boss 接触は未確認 |

## #728 オンラインのリモート味方へのスーパージャンプ先（再現せず）

| 項目 | 内容 |
| --- | --- |
| 報告内容 | リモート Actor は `Actor.update()` を通らないため `rememberSuperJumpGround()` が呼ばれず、最終接地点が古い／復活後に失敗する |
| 調査結果 | 現 main の合成済み `NetMatch.applyRemote()` は末尾で `a._finishFrame(dt)` を呼び、スーパージャンプパッチが `_finishFrame` の先頭に `rememberSuperJumpGround(this)` を入れているため、受信サンプルごとに同じ規則で更新されている。復活直後は `spawnPending` の間（旧ライフのサンプル）だけ更新されず、最初の新しいサンプルで再構築される |
| 対応 | コード変更なし。受入条件（最新の接地点、空中・壁・飛行で上書きしない、復活後の再構築、履歴の無い相手は拒否）を実 `NetMatch.applyRemote` + 実 Actor の回帰テストとして追加し、未変更の main 合成で通ることを確認した |
| 確認状態 | ロジック確認済み。2 クライアントのブラウザ実通信は未確認 |

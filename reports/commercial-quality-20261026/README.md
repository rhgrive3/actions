## 検証条件の制約と残る出荷確認

1. **実機性能・操作:** iPad/Safari、物理Joy-Con、実GPU、長時間連続試合、実際の二端末対戦は未確認。描画や入力の改善量をこれらの実機FPSへ換算していない。本家Switchとの完全な操作・判定一致も認定していない。
2. **アカウントを含むブラウザ受入:** アカウント付き配信物を既存の静的ゲーム検査サーバーで開く試行は、`/api/account/session` が存在しない404をconsole検査が正しく失敗させた。ページ例外はなく、585応答は照合できたが、この試行を成功と数えない。検査のエラー条件は緩めず、ゲーム単体を本来の条件で再検証した。アカウントはWorker/API試験、実ストリーム、実UI式の回帰、Vite本番ビルドで検証した。配備先相当のAPIとブラウザを通した一連の確認は残る。
3. **セッション境界:** 今回の追加修正は同一タブの既存確認と5つのセッション変更を調整する。別タブ、その他の認証API、ブラウザが既に処理したCookieの巻き戻しを原子的に制御するものではない。
4. **Service Workerの専用実ブラウザ検査:** 実行基盤ライブラリへのアクセスとして自動承認レビューに拒否されたため、専用のnative Service Worker検査は未実施。拒否の回避・再試行を行わず、ロジックと実HTTP中断の検証を行った。ゲーム起動のブラウザ結果をこの専用検査の代用として扱わない。
5. **LFSと原典ステージ:** 大容量の事前変換済みLFS payloadは未取得。今回の基準・候補ビルドはともに既存のブラウザ変換フォールバックを使用した。実配備対象のアセット構成と起動負荷は別途確認が必要。
6. **既存の環境依存試験:** worker-template-compactionの4試験は既存の `/mnt/workspace` 前提ガードで止まり、アサーションまで到達しなかった。ガードを変更せず、実際の本番生成workerとサイズ検査を通した。全選択を一つのNodeプロセスに集約した試行は約2GiBのヒープ上限へ達したため、同じ試験を領域ごとの別プロセスに分割した。実HTTPのloopback制限は許可された同一試験の再実行で解消した。元の失敗ログも保持している。

公開中のPR #1882とはファイルの重なりがあるため、将来mainへ取り込む際は最新差分の再確認が必要。今回そのPRを取り込んだり、外部ブランチへ変更を送ったりしていない。

納品ZIPは新規の配信用フルアセット一式ではなく、**基準版へ適用する全変更**を含む。`changes.patch`、変更後ファイルの `overlay/`、この報告・証跡、基準と変更後ファイルのハッシュ一覧を収録する。パッチとoverlayは同じ変更の二つの受取形式であり、両方を続けて適用する必要はない。

既存のGitチェックアウトでは、未保存の変更を退避してから基準版の新しい作業ブランチを作り、パッチを検査・適用する。

```sh
git switch -c local/inkwave-quality-20261026 e781229bac5e8ba61f9bcf7f1c965e54db55afb4
git apply --check /absolute/path/to/changes.patch
git apply /absolute/path/to/changes.patch
```

別のmainへ直接上書きせず、差分をレビューして取り込む。対象の基準版への `git apply --check` と適用後のファイルハッシュ一致は、納品時に一時indexで検証している。

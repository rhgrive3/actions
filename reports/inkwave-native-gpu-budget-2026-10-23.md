# 原典ステージの GPU 描画負荷とコンテキストロスト対策（2026-10-23）

対象は公開版 `inkwave-public/` に合成される原典ステージ（`patches/native-stages/`）。報告された症状は「ネイティブステージが重すぎて GPU 描画が落ちる」（WebGL コンテキストロスト）。

## 計測方法と区別

- 種別: **Chromium + SwiftShader での WebGL 確保量の集計**。`bufferData` / `texStorage2D` / `texImage2D` / `renderbufferStorage(Multisample)` をフックし、各オブジェクトの最新サイズを合計した概算（ミップを含む。ドライバ内部の余剰は含まない）。
- 実 GPU の VRAM 実測、フレーム時間、実機（デスクトップ GPU・iPad 等）での落ちの再現は**未確認**。SwiftShader のフレーム時間は参考にならないため判定に使わない。
- 条件: 1280×720、deviceScaleFactor 2、設定 `quality: high`、Turf、easy、ステージはクサヤ温泉（`brinewater`）。ゲーム開始直後に固定フレーム 4 回描画。
- 計測ツールはリポジトリに含めない（スクラッチ）。原典画像・モデルは保存していない。

## 変更前（main `726e338`）

| 項目 | 値 |
|---|---|
| 1 フレームの draw call | 834 |
| 1 フレームの三角形 | 1,885,764 |
| レンダーバッファ（MSAA×4 HDR + 深度, 1920×1080 相当） | 272.7 MB |
| テクスチャ（原典 520 枚・塗り atlas 4096・影 4096・ポスト処理） | 623.9 MB |
| バッファ | 116.7 MB |
| 合計 | 約 1013 MB |

ウナギ（`eeltail`）でも 783 draw call / 1,908,302 三角形 / 合計約 846 MB。

主因:

1. **GTAO の法線・深度パス**が `scene.overrideMaterial` で原典表示メッシュ全体を毎フレーム再描画する。三角形・draw call がほぼ倍になる（通常ステージのタイドウォーターは約 87 万三角形）。
2. **MSAA×4 の HalfFloat 合成ターゲット**が画面解像度 × pixelRatio 1.5 で確保される。1080p 相当で約 270 MB、4K 相当では約 4 倍。
3. 原典テクスチャ（high では法線・ラフネス・発光マップ込みで約 320 MB。512px 以下が中心のため既存の寸法上限はほぼ効かない）。

## 対策（`patches/native-stages/runtime/native-gpu-budget.mjs`）

原典ステージを公開している間だけ、利用者の品質設定の上に上限をかける。CPU の塗り・物理・ナビ・アクターには触れない。

- 段階 0（全原典ステージの既定）: GTAO 無効、MSAA ≤ 2、pixelRatio ≤ 1.25（デスクトップ。タッチ端末は既存の上限のまま）。
- 段階 1（原典ステージで 1 回コンテキストロストした後）: MSAA 0、ブルーム無効、pixelRatio ≤ 1、影 2048、塗り atlas 2048、テクスチャは `balanced`（法線・ラフネス・発光マップなし、1024 上限）。
- 段階 2（2 回目以降）: pixelRatio ≤ 0.75、影 1024、テクスチャ `low` かつ 256 上限。
- 段階は `localStorage` の `inkwave.nativeGpuSafety` に保存し 14 日で失効。コンテキストロスト時の再読み込みダイアログに、次回から負荷を下げる旨を追記する。
- 通常ステージへ戻ると上限を外し、元の品質（GTAO・MSAA×4・影サイズ）に戻す。

## 変更後（同条件）

| 項目 | 変更前 | 段階 0 | 段階 1 |
|---|---|---|---|
| draw call | 834 | 458 | 447 |
| 三角形 | 1,885,764 | 1,103,827 | 1,118,549 |
| レンダーバッファ | 272.7 MB | 143.9 MB | 26.0 MB |
| テクスチャ | 623.9 MB | 590.6 MB | 256.8 MB |
| 合計 | 約 1013 MB | 約 852 MB | 約 397 MB |
| 原典テクスチャ枚数 | 520 | 520 | 170 |

ブラウザでの確認: 原典 → タイドウォーター → 原典の切替で `R.q` が上限付き → 元設定（AO 有効・MSAA 4・pixelRatio 1.5）→ 上限付きに戻ること、原典ステージ上の `WEBGL_lose_context` で段階 1 が記録されダイアログに説明が出ることを確認。ページエラーなし。

## 挙動への影響（スプラトゥーン3 との比較）

描画表現だけの変更で、移動・射撃・塗り判定・インク回復・カメラ操作のロジックは変えていない。本家との挙動差の記録（`inkwave-splatoon3-behavior-2026-10-02.md`）の既存項目は解消・変更扱いにしない。段階 1 以降では塗り atlas が 2048 になり、塗りの見た目の解像度が下がる（CPU の塗り所有・スコアは同じ）。

## 未確認・残件

- 塗り重ね描画用ジオメトリ（非インデックス、1 頂点 80 バイト）とテクスチャ側の更なる削減は今回未着手。

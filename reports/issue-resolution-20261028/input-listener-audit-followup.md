# Input listener audit follow-up

The hosted component and source tests used a fixed expectation of ten listeners per Input. The pointer-lock lifecycle legitimately adds two more, so the tests now check each instance's actual `(target, type, callback, capture)` ownership, removal and repeated disposal. The browser observer also checks window, document and canvas; signal-owned listeners; the touch layout sampler's explicitly disposed subscriptions; keyboard controls; and independently registered sentinels. Existing renderer, shadow and reflection checks remain. The Node 22 source and observer tests pass 16/16, including intentionally leaked targets, wrong capture, an un-aborted signal, an undestroyed layout sampler, a leaked key listener, non-idempotent disposal and removal of a foreign sentinel. These changes modify test infrastructure, not product input code.

# Charger fired-shot Sub admission (#837)

Base: current868327651d2 composition; relevant16F finite-flight writer and action modules match the preceding audited402802/c1b9 graph. Claim: https://github.com/rhgrive3/actions/issues/837#issuecomment-6024339447. #844 charge-interruption Sub timing is intentionally a separate root.

The old behavior was reproduced through real Actor input and the installed finite-flight owner, including the existing1F release gap: a valid partial shot creates flight1 at tick16 and starts the16F squid clock, but Sub aim begins at17. An R tap during relative ticks1–2 produces a bomb at6; holding R until relative16 produces a bomb at16. These are actual preparation and throw observations, not inference from a missing wrapper.

A pure shared predicate reads the existing16F shot clock. Sub becomes legal when only its final1F remains, giving15F fired-shot recovery without creating or advancing a second timer. The native-input view reads the predicate dynamically so a shot admitted inside an update cannot bypass the subsequent Sub gate. The outer existing SubReady owner uses the same predicate before starting preparation and clears same-tick rejected preparation after the nested update. Normal idle/main-only Charger input does not allocate this extra view.

After: held R first aims at relative15 with SubReady age0. Releasing at16 throws at20 using the existing readyTimeKid5/60, i.e. six updates including the preparation start. The15F gate and16F squid clock are not added serially, and the existing preparation period runs only once. A press/release wholly inside the blocked interval is discarded and produces no delayed bomb, matching the existing generic post-shot input-discard contract. No projectile, damage, charge payment, stored-charge, refill or next-main timing owner is replaced.

Validation:11 source cases cover actual partial/full shots at30/60/120Hz, start/throw boundaries, the retained16F clock, blocked taps, insufficient ink, reset, death, special, Super Jump, ghost playback, and non-fired cancellation. Cancellation still has no fired-shot gate, preserving the separate unfixed #844 behavior. Ghost playback produces a visual flight without starting local post-shot/SubReady state. No new build/browser or complete CI was run.

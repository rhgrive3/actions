# アメフラシ境界の遮蔽・負荷検証（採用保留）

**一般採用は保留。** 屋根下への誤表示は修正・検証したが、8雲同時再構築のCPU p95が23.6msで、60Hzの1フレームを超えた。原典ステージの実データ取得も失敗した。軽量な一般改善として完成扱いしない。原実装・証拠はcommit `1949434f6e087c648ee990d16efbc665ff8cb6bb` に保存済み。その親は指定基準 `a4e81347906c0d60ceef76a69f476261bf8d3f86`、tree `34236683e6776aac9d8b1d4ae0b8a1b31d3f2df2`。

## 原因と修正範囲

初版は全受け面に円筒の外周を描き、上方の遮蔽物を確認しなかった。通常の深度テストはカメラの遮蔽を扱うので、雨の遮蔽の代用にならない。検査表示で、雨レイが屋根Y=2.8で止まるのに床Y=0の輪郭が描かれることを再現した。

`storm-boundary.mjs` と新規 `storm-boundary-occlusion.mjs` の専用処理に絞った。既存Physicsの衝突箱／原典TriangleWorldの三角形から垂直遮蔽領域を作り、受け面を切り取る。露出した各受け面につき一度、**既存の `G.physics.raycast`** で照合する。原典のチャート外接矩形は使わず、BVHの近傍候補から元三角形を直接取る。全チャートの三角形リストは走査しない。

受け面自体も、照合前に収集範囲へ切り取る。これがないと大きい床の照合点が範囲外へ出て、収集対象外の遮蔽物に当たり、境界全体が不要に消える場合があった。移動する衝突箱の変化、雲の高さ・近傍の変化でキャッシュを無効にする。安定フレームは照合レイ0本。数値許容差は面の描画オフセット0.006WU、遮蔽切断0.012WU、レイ照合0.02WUで、微小な接触隙間の厳密一致は保証しない。

通常塗り・攻撃・投擲・物理・通信・発動や操作ロック時刻は変更しない。髪、モデル、他スペシャル、共通シェーダー／材質も変更しない。`paint.splat` は呼ばない。

## 生ソースと実行コードの半径・寿命

生の `inkwave-public/src/game/weapons.js` は塗り標本・Actor判定に全半径を使うが、公開ビルドの合成後は次の処理になる。

```js
const s = stormRainScale(c);
const r = Math.sqrt(Math.random()) * (sp.radius * s);
if (!stormRainContains(c, e, sp.radius, s)) continue;
if (c.t <= c.dur + 1e-10) { /* rain */ }
```

したがって全半径10WUへ境界だけを広げる修正は行わない。実行コードの横方向の塗り標本・Actor判定と同じ `sp.radius * s` を維持する。雲age=1/60の約3.67693WU、age=7.6秒の約7.33333WUを、実Projectilesの内外Actorへのdamageと塗り標本で確認した。初版の境界だけが0.3秒早く消えていたため、実際の雨の寿命 `dur` まで描くよう修正した。

境界の垂直遮蔽は、既存の表面塗り用レイ（雲Y−0.8、下向き12WU、grateを省略しない）に従う。Actorには足元＋1.2やLOSの別条件があり、その3D体積全体と同一とは認定しない。これらの既存ゲームロジックは変更していない。本家との距離・遮蔽・線幅の一致も未認定。本家の根拠は親のencoded 30fps f173–183の観察のみで、本担当は映像を直接閲覧していない。

## 遮蔽・ライフサイクル検査

通常ゲーム画面は標準の試し撃ちを起動し、実Character・Q発動→Sub押下／解放・通常followカメラで撮影。初期位置とゲージのみ制御。検査表示は別の床・屋根・壁fixtureで、同じ保存済み候補モジュールと実Physicsを使用する。

| 検査表示 | 対象床点周囲の境界画素差 | 結果 |
| --- | ---: | --- |
| 屋根なし | 46 | 描画する |
| 一部遮蔽 | 0 | 屋根下を除去し、露出側は残る |
| 完全遮蔽 | 0（画面全体も0） | 全て除去 |
| 屋根が範囲外へ移動 | 46 | キャッシュを更新して復帰 |
| 壁→床 | 77 | 継ぎ目を保つ |
| 非塗布面 | 0 | 描画しない |
| 雲より上／到達範囲外 | 0 | 描画しない |

幅0.02WUの細い屋根も、点サンプリングに頼らず幾何テストで除去した。元の1949434を戻したnegative controlは一部遮蔽の対象点に46画素を出し、遮蔽検査を通らない。新候補は通る。

関連46テスト成功。expiry、clear、二重release、死亡後の既存雲継続、再利用、予算超過時の全消去を含む。通常ブラウザの30/60/120Hzフレーム投入は各123固定tickで、元版と状態trace hash・塗りgrid hashが一致。移動・終端まで境界が追随し、simf600では雲も境界もない。simfはSub解放からのINKWAVE simulation ticksで、参照録画フレームではない。source所有権・Pages identity 16検査、production build、startup budgetも成功。

## 処理量と採用を止めた測定

上限は、近傍箱128、原典候補512、BVH調査2048（超過検出のコールバック1回は別）、遮蔽切断4096回（別途、受け面の近傍・高さ切り取り）、照合レイ64本、分割polygon512、生成頂点8192。位置属性の保持上限は約98KB／雲で、既存ステージのBVHや全データを新規複製しない。上限超過・Physicsとの不一致・必要なAPI欠落時は**全境界を非表示**にし、一部だけを雨域として残さない。

Chromium／SwiftShader、960×640。通常場面は追加1 draw・152 triangles・位置属性5,472 bytes。CPUの単体再構築20回は中央値1.0ms／p95 7.4ms、安定フレーム0.010ms・レイ0本。別の8雲同時試験12回は中央値4.7ms／p95 **23.6ms**、112レイ／同時再構築、位置属性合計43,776 bytesだった。描画自体のon/off中央値差はノイズ範囲で、無負荷や高速化は主張しない。CPU再構築の外れ値を許容して一般採用する判断もしない。

原典取得が失敗したため、下表は**人工グリッド**である。実際のBVH builder、TriangleWorld、NativePhysicsをブラウザで動かし、同じ範囲を照会した。原典ステージの実測の代用とは扱わない。

| 人工衝突データ | BVH調査／近傍候補 | 全チャート読込 | 8雲再構築 中央値／p95 | 8雲位置属性／draw |
| --- | --- | ---: | --- | --- |
| 2,048三角形 | 288／200 | 0 | 7.9／8.9ms | 67,392B／8 |
| 131,072三角形 | 288／200 | 0 | 4.9／16.9ms | 67,392B／8 |
| 高密度32,768三角形 | 513／512で停止 | 0 | 0.6／0.9ms | 0B／0（全非表示） |

同じ人工データの1949434では、13万三角形の全チャートを再構築ごとに走査した。高密度ケースの8雲は位置属性約9.44MB、再構築中央値32.4ms／p95 110.4msだった。ただし新候補はこの高密度ケースを描かないので、同等の表示を保った高速化という比較ではない。テストでは全チャートgetterを禁止しても候補が通り、原典候補の上限超過とレイ上限超過の両方で部分境界0を確認した。

次の具体案は、(1) 全境界を隠したまま再構築をフレーム単位の仕事量へ分割する、(2) 同じ高さ・静的近傍の重なる雲で遮蔽ジオメトリを共有する、の2案。前者は表示遅延と全体スケジューラ、後者は参照数・移動物・高さの無効化を追加検証する必要がある。今回はその複雑さを導入せず、測定済み候補の保存までに留める。

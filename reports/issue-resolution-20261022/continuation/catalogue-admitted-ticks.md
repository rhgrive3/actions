# Catalogue sidecars follow accepted owner ticks

A rejected future owner tick could still replace its actor's sub/Special kit. The catalogue wrapper checked that the incoming timestamp was newer, but did not check whether native `_tick` actually accepted it. The fix also requires the post-call peer watermark to equal that timestamp. Existing membership, actor owner/life, catalogue choice and return-value behavior remain intact. A malformed optional `ck` still drops only that feature while a valid native body/timestamp progresses.

The production-composed legacy counterexample accepts `1000/torpedo`, then rejects `1014/bomb` at the native clock gate while previously changing the kit anyway. Independent before/after controls reproduce three old failures (prebind, future, malformed event envelope) and pass all four fixed legacy cases. New positive controls change the sender's real kit and serialize it through `_sendTick`; no invented timestamp makes recovery pass.

The new real-session test uses two production-composed `NetSession._begin`/`_message` graphs, actual Actors/WeaponRunners and actual WebCrypto nonce queries/replies. Future, stale, foreign and malformed-envelope messages preserve accepted state; subsequent real kit/body updates work and a wrong-life sidecar still rejects.

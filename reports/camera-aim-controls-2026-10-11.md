# INKWAVE カメラ・照準・入力 改修報告

基準: `f2c870859d637fccba88031c3786ecec4d95248d` / 参照版: Splatoon 3 Ver.11.3.0 / 作業日: 2026-10-11

## 到達点

実配信ビルドに読み込まれるコードへ改修を組み込み、ローカルビルドと選定回帰テスト 165 件を完了した。
**本家との完全一致、実機操作、実ゲームの描画成功を証明する成果ではない。**
WebGL を初期化できず、実ゲームと本家の同条件画像・動画比較は未完了。
Drive の読取は成功したが、現在公開されている接続操作には upload/create がなく、納品ZIPのDrive保存も未実施。
本ローカル検証時点ではGitHubを変更していない。後続のPR移植は上記追記を参照。

## 1. 入力と配信経路

指定Drive ZIPを取得・解凍し、その内容をローカル差分の基準とした。
ZIP SHA-256: `534d397c96ce5db65f4d833c91f7ceab69d6529d9c4f5edf33748429a9d448f7`

`inkwave-public/` の不変ソースへ直接上書きする方式ではない。元の6段階の変換後に
`patches/splatoon3/camera-aim-controls-adapter.mjs` を適用する。
元ソースと複数の変換後の意味が異なっていたため、公開用の最終合成を検証対象にした。
新しい統合アンカーは欠落・重複時にビルドを失敗させ、黙って修正が消えることを防ぐ。
2種類の主要VM fixtureも同じ `adaptBuildSource()` を使うよう統一した。

## 2. 実装した変更

| 対象 | 修正内容 |
|---|---|
| 発射時の照準 | Controller更新後、Actor/Weapon更新前に現在tickの入力角度で照準を再構成。描画カメラやばねを二重更新しない。 |
| 入力直後の壁際 | 入力によって回転・移動したシミュレーション用カメラ原点も衝突検査。まだ描画していない1tickの壁抜けを防止。 |
| カメラ衝突 | 衝突上限から1.6mはみ出してよい処理を削除。0.45mの最小距離が近い壁を貫かないよう制限。 |
| 最終カメラ位置 | 肩オフセット・揺れ・遷移ブレンド後に中心と可視near-plane四隅を実Physicsで検査。 |
| スコープ | 通常チャージャーの不要なズームを停止。`WeaponScopeParam`が空オブジェクトでもスコープ能力として認識。 |
| 4Kスコープ | 同梱の11.3.0カタログに明記された `CameraFovy:20` を適用。 |
| ズーム遷移 | charge=0.99の境界ジャンプを除去。武器・イカ形態への切替でズーム残りを消す。遷移曲線自体は暫定。 |
| レティクル投影 | 描画用とゲームプレイ用の投影行列に残っていたFOV更新しきい値差を除去。 |
| 銃口と近距離 | 2m未満で一律に照準収束を無効化する処理を廃止。ゼロ距離・後方ターゲットは射線反転させない。 |
| 壁際の銃口 | 不正なXYZを排除し、フォールバック銃口も実Physicsのレイで遮蔽物の手前に戻す。 |
| スティック積分 | 指数平滑値の終端値×dtから厳密な時間積分へ変更。マウス変位にdtを乗じない既存仕様は保持。 |
| ジャイロ所有権 | センサー報告がないtickでもジャイロ有効中の右スティック上下を抑止。非対応・未接続ではスティックへ戻る。 |
| HIDサンプル | 実WebHID接続では3個×5msのIMUサンプルを全て積分し、報告ごとの角度を一度だけ消費。報告間の変化の取りこぼしと同じ速度の再生を防止。 |
| 入力の境界 | マップ・メニュー中のHID報告を蓄積しない。復帰時、再センター時、切断時の残留角度を破棄。 |
| スーパージャンプ | 自動yaw/pitch更新の後にカメラ後方ベクトルを同tickで再計算。 |

既存のエイムアシストは配信コードで既に無効だった。この改修で新しく無効化したとは扱わない。
弾道・重力・ダメージ・塗りの計算を直線弾へ置き換えていない。既存の弾道収束とガイドを保持する。

## 3. 同一条件の修正前後計測

同じ計測スクリプトから、それぞれの**生成済み配信モジュール**を実行した。
キャラクターメッシュ・音声・GPUはfixtureの対象外。物理衝突検査では実際の `Physics` を使用。
以下は本家との実測比較ではなく、指定mainと改修版の比較である。

| 計測 | 修正前 | 修正後 |
|---|---:|---:|
| 通常チャージャー満充電FOV | 43.805605° | 55.000000° |
| 4Kスコープ満充電FOV | 54.994395° | 20.000000° |
| 衝突上限0.1mに対するboom長 | 1.700000m | 0.100000m |
| 90°入力直後の照準角度誤差 | 90.000000° | 0.000000° |
| 30fps描画・60Hzシミュレーション、90°/秒旋回の最大照準遅れ | 3.000000° | 0.000000854° |
| 入力更新を30/60/120Hzで直接呼んだ場合の1秒後の角度差 | 1.573497° | 6.54e-13° |
| 近距離テストの銃口→目標方向誤差 | 23.198591° | 0.000000° |
| 4画面比率の投影行列要素の最大不一致 | 0.000186844 | 0.000000000 |

通常のゲームシミュレーションは改修前から60Hz固定。
「入力更新を直接30/120Hzで呼ぶ検査」と「実際の固定60Hz＋描画30/60/120Hz」は別の試験であり、混同しない。
近距離テストは銃口(0.3,1.05,0.3)m、目標(0,1.05,1)m。
画面比率は16:9、4:3、21:9、9:16。数値の全桁・条件は同梱JSONに記録した。

## 5. テストと実行手順

Node 22.16.0で実行。選定スイートは 21 ファイル、165 テストが成功。
新規カメラ試験、HID積分・所有権、感度、固定クロック、照準、銃口、安全な金網通過、塗り得点、通信イベント、
スーパージャンプ、既存カメラ肩位置・揺れ・プローブキャッシュを含む。
これはリポジトリ全CIやライブ対戦、実機ジャイロの合格を意味しない。通信はローカルのpack/playback等の回帰。

```sh
# 指定baselineを展開したリポジトリへ、同梱パッチを適用後に実行する。
node scripts/test-camera-aim-controls.mjs .camera-aim-results

# この環境で成功したネット接続・esbuild不要の配信ビルド。
INKWAVE_BUILD_UNMINIFIED=1 node scripts/build-inkwave.mjs inkwave-public _site

# 生成済み配信ソースを使って同じ計測を再現。
INKWAVE_BUILT_SITE="$PWD/_site" node --experimental-vm-modules \
  scripts/measure-camera-aim-controls.mjs after-measurements.json

# WebGLが利用できる環境で練習場を開く。
python -m http.server 8000 --directory _site
# ブラウザ: http://localhost:8000/?range&skipTitle
```

ブラウザ画像取得補助: `python scripts/capture-camera-aim-controls.py http://localhost:8000 capture-output`
Python Playwrightと利用可能なChromiumが必要。これは構文確認のみで、今回の環境では描画成功を検証できていない。
補助スクリプトの30/60/120はエンジンの合成ステップ頻度であり、実ディスプレイのリフレッシュレート測定ではない。

## 7. 未解決・未検証

本家の通常カメラの全パラメータ、加減速・旋回の追従曲線、全武器・スペシャル・死亡/復活の固有カメラ、
スコープの正確な一人称位置・マスク表示・遷移タイミング、全ブキのレティクル開閉形状と拡散表示は一致未確定。
今回これら全てを再実装したとは言わない。

実機のJoy-Con/Pro Controllerのマウント座標系・軸符号・感度曲線、スマホの姿勢変化、センサー遅延、
入力から光子までの遅延は未測定。標準GamepadだけではIMUを得ず、WebHID等の対応が必要。
対応APIがないプラットフォームでコントローラージャイロが利用できるとは主張しない。
既存の端末ジャイロ、反転設定、デッドゾーン、Y再センタリングは回帰対象とし、未根拠の本家定数への置換はしていない。

実ゲームの画面取得はWebGL初期化エラーで止まった。通常のローカルURL参照にもブラウザ管理制限があった。
描画バックエンドを変えた確認でも `webgl:false` だった。成功した画像・動画はない。
納品HTMLの動画比較欄は利用者が2本の実映像を読み込むための補助であり、未取得の本家映像を生成・代用していない。
`webgl-unavailable.png` は失敗画面の証拠であって、ゲーム比較画像ではない。

## 8. 適用・納品上の注意

差分は指定baselineに適用する。新しいmainで同じファイルが変わっている場合は競合を解決し、検査をやり直す。
同梱の `apply.py` は変更前ハッシュが合わないファイルを上書きしない。patch適用とoverlay適用は代替であり、重ねて実行しない。
`changed-files/` は変更ファイルの完全な本文。元のゲーム全アセットを複製したものではなく、指定project ZIPと組み合わせて再構築する。

# #505: team-wide WIPEOUT Flow points

Target: Splatoon 3 Ver. 11.3.0, ordinary Turf 4v4, inactive Flow. The current
community verification lists +10 fp for every teammate on an enemy WIPEOUT,
stacked with the normal kill contribution:
https://wikiwiki.jp/splatoon3mix/検証/イカフロー . This is the explicitly requested
community-verified value, not a claim of independent Switch instrumentation.

The current Match-scoped producer from #540 emits {match, team, sequence}, where
team is the wiped side. This change adds only the offline Flow consumer, after accepted
Actor/remote updates have produced that event. It introduces no second roster
transition detector. The producer remains limited to ordinary 4v4 Turf.

The bonus is normalized by the existing threshold/referenceThreshold pair;
normal damage/splat/assist weights remain separate. Inactive teammates receive
the award even while waiting to respawn, following the source's team-wide rule.
Active Flow is not extended and no paint burst is generated by this team event.
The bonus is progress, not an additional splat or assist; it cannot activate Flow
on its own. Existing final-splat scoring/activation executes in its original
listener before the post-update team event. Physical recipient/activation-order
traces are not independently measured here.

The consumer checks current Match identity, playing/not-paused/time state,
Turf/not-attract, the ordinary roster and zero living opponents. Match-scoped
sequence memory suppresses duplicates/stale sequences, including repeated
installFlow listeners. An intro lifecycle resets the scope when a Match object
is reused. A later accepted respawn re-arms the existing producer for a distinct
wipeout. Both teams can receive their independent bonus on a simultaneous wipe;
HUD presentation priorities remain owned by #540.

Validation:
- Native Actor.splat/damage plus actual composed Match.update/event consumer:
  source7/7, emitted7/7. Tests include a non-wipe splat, final attacker plus helper
  plus untouched/dead teammates, repeated/stale events, respawn/reuse, invalid
  lifecycle/roster, simultaneous wipes, active state and 30/60/120/144 Hz.
- Existing #540 and #489 Flow lifecycle suites:20/20.
- Negative control with the old Flow runtime fails with 0 fp instead of10.
- Exact #549 issue-481 adapter was separately composed onto the #489/#505 runtime:
  actual native final splat gives23 fp, then one WIPEOUT gives10 additional fp to
  the attacker and10 to each other teammate. Re-sampling adds nothing. The #549
  branch itself is not silently included in this batch.
- Production build f5ae304f0e96. Actual app browser proof was added alongside the
  existing WIPEOUT HUD acceptance: native Match transition, team10 fp and duplicate
  event suppression. It awaits the combined CI; no separate source CI was added.

## Online acceptance is blocked by confirmed divergence

The #540 producer currently derives its transition from each client's accepted
roster. The consumer updates all teammate records in that client, including
remote proxies. The tests above prove native Match/bus idempotence, not agreement
between owners under delayed, coalesced or reordered network snapshots. No
cross-peer Flow synchronization or authoritative team-event transport was added.
A two-owner full-roster replay test is still needed to rule out a missed/repeated
transition at death/respawn boundaries. Consequently #505's complete online
acceptance is not claimed, independently of #504's #427/#494 dependency.

Native two-owner/full4v4 replay confirmed both failure directions before the
guard: a delayed natural-respawn packet creates a false local wipe/+10fp, and a
death→natural-respawn pair coalesced before one receiver Match.update misses its
bonus. Ordinary exchange and exact duplicate packets pass, so sequence dedup
alone is insufficient. The final candidate therefore returns early when G.netm
is present. It preserves the existing online behavior rather than enabling
known false awards. #505 remains incomplete online until an authoritative
team-event decision and delivery path is designed and verified.

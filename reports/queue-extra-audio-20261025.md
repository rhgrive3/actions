# Additional audio queue optimizations, 2026-10-25

Base: PR #1870, `8e539eac1e5fe4a6412d3e5852d7f5eaa5d0c1da`.

Seven previously unimplemented audio queue rows now have production changes:

- The recorded Charger excerpt decoder consumes its exact response buffer.
- Authorized MP3s transfer their original bytes only when every declaration for that file has the same normalized SHA-256 and the actual digest has completed successfully. Mixed unsigned or unequal declarations keep the prior copy. The completed digest value is stored without adding another asynchronous scheduling boundary before decode.
- Verified resident/staged PCM can serve a differently named file with the same SHA-256, loop classification, endpoints and seam policy. Both the small-import scan and larger-import index use the same normalized key. This does not promise single-decode coalescing for two simultaneously cold different filenames.
- Manifest-confirmed absent recorded events skip redundant `ensure` promises while keeping the missing-event diagnostic and existing recorded base fallback. Unknown manifests retain their load/retry path.
- Deferred loop handles snapshot changing options until actual playback resolves, then forward updates directly.
- Foley generation removes only the never-read `sources.raw` array/write; its scalar RNG draw and filter sequence remain.
- Guided PCM rendering allocates FFT real/imaginary scratch once per render and clears both arrays before every frame. The classic Worker was regenerated by the repository tool.

The machine-readable [dispositions](queue-extra-audio-20261025.json) cover all 37 audio-related queue rows plus the three additionally requested cache proposals. Seventeen audio rows were already effective in PR #1870, including gain-event deduplication, Worker failure cleanup, lazy music FX, immutable DSP tables, LRU touches, and streamed retirement/recovery. Four rows belong to the UI/workflow owners. Eight audio proposals remain conditional/deferred, with exact ownership/readiness evidence still required; they are not counted as fixed. The unwanted rights audit was excluded under the user's prior instruction.

## Cache follow-up audit

No cache production changes were made. `source-retention.mjs` deliberately revalidates keys and sealed accounting on each separately acquired Web Lock; carrying a snapshot across owners without a generation/invalidation protocol would weaken cross-tab mutation and quota recovery. The five-second slot proposal similarly needs a loader-owned bounded session with completion, abort and stage-switch teardown. The incremental SHA-1 proposal already has a measured rejection in `reports/queue-native-20261022/README.md` and `tools/benchmark-source-sha1.mjs`: preserve native WebCrypto rather than introduce synchronous CPU regression without new evidence. Exact per-row constraints are retained in the JSON.

# Further INKWAVE calculation reductions

Production base: `f11d7e2d8908f61dcb4ef6b42d0a20aa9dcb993a`. The two motion preimages are unchanged since `07f44b97`; their frozen hashes are checked by the regressions. Existing A*, paint-distance, FK, offscreen/intermediate-tick, normal-readback and GPU quality budgets remain in place. The public `inkwave-public/` snapshot stays untouched.

## Adopted changes

1. **Root hair spring propagation.** Each existing segment retains one last K/D/dt propagator, shared by its three axes and subsequent equal ticks. Changed dt or coefficients recompute it; signed zero is distinguished. Variable time steps reuse the same record, without a per-frame allocation or a history of visited times. The exact Float64 expressions, saturation, reset, authored motion and bone transforms remain unchanged. In six strands × four segments, 120 warmed fixed ticks previously performed 8,640 calls to each of sqrt/exp/cos/sin for spring coefficients; now each is zero. A changed tick uses 24 of each instead of 72. There is one small record per existing segment, at most 32 for the native eight-strand rig, released with its owner; this is bounded extra storage, not a memory-reduction claim.
2. **Source-pose Euler conversion.** Reuse the exact `sin(±0) = ±0` and `cos(±0) = 1` coefficients in the existing Three.js ZYX expression. Nonzero angles use the original transcendental functions and expression order. Quaternion input, blends, source coefficients and FK remain intact. A 360-frame original WalkHold sample needs 71,280 → 36,360 sine evaluations (48.99% fewer), with the same cosine reduction. There is no new pose cache or retained buffer.
3. **Native texture material membership.** Build the file-to-material association once per load instead of filtering all materials after every decoded file. Associations include unrequested map roles, deduplicate a file repeated within one material, preserve material order and the existing last-role precedence, and disappear with the loading jobs. The 96-material/48-selected-texture control reduces material table enumeration 49 → 1 and map enumeration 4,512 → 96. Decoding, filters, dimensions, pixels, color space, channel inference, ownership and abort cleanup are unchanged. This is loading CPU work, not a GPU-memory or decoder-peak claim.

The private loader entry is bundled separately with production options and bound to the production inputs; it is not described as a separately shipped module.

## Investigated and rejected

- A bounded last-quaternion cache eliminated 57% of Euler conversions but regressed the paired Node Character owner median by approximately 4.7%. It was removed, including its 11,016 bytes of bank storage. The adopted zero-coefficient path avoids the lookup/storage cost.
- Direct decode-and-resize would avoid returning a full-size intermediate ImageBitmap. Chromium preserved all random RGBA control pixels, but WebKit changed 423–11,792 channels (maximum difference 36) across four controls. This path was not adopted. The current two-step decoder and native texture limits stay in place.
- The remaining measured owner work is primarily quaternion interpolation, required FK, source polynomial evaluation, IK/collision and rendering. Skipping these, changing the existing visual budgets, removing composer/reflection work or reducing texture quality requires further equivalence/device evidence. Open #642, #845, #923 and the calibrated whole-game benchmark #1434 are not established complete by component measurements.

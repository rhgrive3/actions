# INKWAVE 2026-10-25版・17項目の修正と検証

## 適用対象と結論

指定された `INKWAVE-main-b1f571da-20261016-edit` の最新ポインタと GitHub main が指す **`7f863ea2d65671abd1453fdae1b61de00f1d10e2`** を基準に、ローカルの修正ブランチで作業した。対象は公開版 `inkwave-public/` に適用されるビルドアダプターと runtime。4並列でモーション、塗り・飛沫、スペシャル・照準、チャージャー・音声を担当し、共通ファイルを統合した。

**1–5・7–17では、原因を確認できた箇所にコード修正を入れた。6の「全体的にスペシャルが早い」は、共通換算が未校正であることと、ブキ別の過剰な塗りが混在しており、解決済みとは扱わない。** また4の全関節軌跡、5の未整理の全差分、8のR-PEN専用音源、11の厳密な床マスクを本家と一致済みとは扱わない。

基準は Splatoon 3 **11.3.0** の公開抽出で、既存カタログの固定コミットは `7280ff9cde8bb1c5dcef46c700c326471584d2e6`。公開された検証者自身の実測表を補助資料として用いた。受領した54ページの資料は主としてシューター・スピナーの精度とギアを扱っており、今回の全17項目の実測根拠にはならない。Switch実機・同条件の映像比較は行っていない。

## チャージャーの線幅

線の塗りと、地形へ直接当たった場所の塗りは別のパラメータである。変更前は接触半径を飛翔線上に短い間隔で連打していた。変更後はチャージの最低受付時間を考慮して補間し、sourceの線の横半幅・縦半幅・重なり率で配置する。配置距離は物理の固定ステップをまたいで保持するため、短いフレームほど密に塗ることはない。

| 追加ブキ | フル時の旧・線に流用していた半径 | 修正後の線の横半幅 |
| --- | ---: | ---: |
| スクイックリン | 3.845 | 1.85 |
| スプラスコープ | 3.085 | 1.4825 |
| リッター4K | 3.845 | 1.85 |
| 4Kスコープ | 3.69 | 1.7725 |
| 14式竹筒銃 | 2.557 | 1.23 |
| ソイチューバー | 3.949 | 1.9 |
| R-PEN | 2.808 | 1 |

これはカタログの11.3.0値とruntimeの照合であり、画面のピクセル幅ではない。始点の1.2 WUや既存のインク輪郭・縦方向表示校正はINKWAVEの規約を維持している。竹の全連射位相、先端塗り、坂道上の全マスクまで本家と一致したという意味ではない。[P1]

## #6を未解決として残す理由

`PaintSystem` は新しく所有した床セルの面積を返し、`Actor.addTurf` はその面積を1:1で `stats.turf` とSPへ加算している。同色の塗り直し、本体と遅延成長、壁、スペシャル使用中のロック、SCUギアの再適用を追跡したが、共通の重複加算は確認できなかった。

公開検証Wikiは「水平に1発ずつ撃ち、ナワバリのポイント表示で平均する」という測定法を明記している。[P2] これと比較するため、実際の本番compositionのProjectile・CPU PaintSystemを使い、未塗り平面、水平照準、固定した発射高さ1.05 WU、セル.25 WUで測定した。乱数3系列×同じActorで15発、**各条件45発**。発射ordinalを保持し、各試行1発のみ受理され、初期＋遅延塗りの加算が実際の所有面積と一致することも検査した。

| ブキ・状態 | INKWAVEの平均面積＝現在の加算量 | 公開実測のポイント | 比較の意味 |
| --- | ---: | ---: | --- |
| スプラシューター | 19.63194 | 4.0 | native実装でも差がある |
| スプラチャージャー・最小 | 20.44167 | 6.8 | fullとは塗り形状が異なる |
| スプラチャージャー・full | 75.20556 | 23 | 変更していないnative経路 |
| リッター4K・最小 | 16.22778 | 6.6 | 今回の線幅修正後 |
| リッター4K・full | 92.85417 | 32 | 今回の線幅修正後 |
| わかばシューター | 31.90694 | 4.5 | 全ブキ共通の比ではない |
| シャープマーカー | 25.67917 | 4.1 | 全ブキ共通の比ではない |

公開表はVer.11.0.0表記。1100と1130の `WeaponShooterNormal / First / Precision` と `WeaponChargerNormal` はファイル全体が同一、`WeaponChargerLong` はインク消費上書き2項目のみ異なり、塗り・弾道項目は同一だった。ただし、共通の非公開スコア計算まで同一だと証明したものではない。[P1][P3]

本測定は本家と銃口・発射間隔・足元周期・塗りテクスチャを合わせた実機比較ではない。面積とポイントの係数に加え、INKWAVEの塗り形状が混ざる。例えば.3倍ならnativeスプチャfullは約22.56pとなる一方、わかばは約9.57pで公開値4.5pからなお大きく外れる。**一つの値を本家の係数として採用する根拠は得られなかった。** SPだけを縮小すると、p表記のHUD・結果との単位もずれるため、今回その暫定倍率は入れていない。

今回の広すぎるチャージャー線・過剰落下滴の修正は、その塗りから得るゲージ量も減らす。ただし、それを「全体の蓄積速度が本家どおり」とは扱わない。次の確認は、同条件の本家とINKWAVEについて、塗り形状・ポイント・ゲージを同時に記録し、世界面積→得点の共通変換とブキ別形状を切り分けることになる。

## 音声の確認範囲

スプラチャージャー専用の録音フレーズを、スクイックリン・リッター・竹・ソイチューバー等のチャージ時間へ流用しないようにした。各ブキの既存MP3の開始音を一度再生し、満充填の通知は実際のcharge境界で発生する。音源全体を無理に伸縮して他ブキへ当てはめていない。

**R-PENは、利用可能な録音パックに専用素材がなく、既存の `s3-charger-pencil → s3-charger-light` の音源借用が残る。** 正しいcharge境界へ接続したことと、固有の音色を取得したことは区別する。実機同録音との波形・聴感の完全比較も未実施。

ホクサイは、長い移動録音のwindup重複だけを除いた。接地しながら引く音はloopとして継続し、入力終了・空中保持で停止する。音声バイナリの新規追加・差し替えはない。

- `npm test`：全工程PASS。Node側20＋18＋27＋24＋28件、Python側13件に加え、既定のビルド互換・移行監査・性能検査を実行。
- 既存VFXの故障注入テストは、ジャンプspinと一緒に共通時計の宣言まで削除して全件ReferenceErrorになるmain由来の不具合を修正。期待される失敗6ケースを名前で確認し、候補の全正例を維持した。
- Chromiumの実DOM：4画面×7系統＝28表示、リサイズ、実投影点・発散の位置を確認。[結果](reticle-viewport-20261025/results.json)

- 第三の担当による統合差分レビューでcritical/majorの新規問題は見つからなかった。レビューは実機比較の代わりではない。

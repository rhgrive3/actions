# Super Jump flight HP recovery (#856)

Base: PR868 c1b9cf4e270c34d6afe0a5a8964ad49a22f9f739. The issue had no assignee/comments or matching fix PR; movement coordination found no overlapping work. Start comment: https://github.com/rhgrive3/actions/issues/856#issuecomment-6023594281.

An actual Actor entered Super Jump through its normal admission and charge transitions. With HP50, expired recovery delay and ink20, another30 fixed flight ticks left HP50 before this change. The current profile's ordinary12.5 HP/s recovery implies56.25 for the same half-second. The fixed actor reaches56.25 while retaining ink20.

The existing HP-only expression is now shared by normal updateResources and the flight early-return path. Ticks that begin in charge still call the existing full resource update once, including the takeoff tick. Ticks that begin in flight recover HP once, including landing, and do not run surface sampling, enemy-ground damage, ink refill or resource clocks. Dead actors and remote proxies do not gain newly simulated flight recovery. The regular resource path and existing allied/enemy Storm choice remain unchanged.

Validation: eight focused source cases cover30/60/120Hz presentation schedules over fixed60Hz simulation, stale submerged/enemy flags, no ink/resource-clock update, configured recovery delay, cap100, allied/enemy rain, dead/remote ownership, takeoff and landing. The existing actual Actor/Character #744 charge exposure test also passes with flight HP expectations updated independently of its preserved ink/exposure assertions. The pre-fix actual flight trace remains the negative control.

Reference and limits: the [community system verification page](https://wikiwiki.jp/splatoon3mix/%E3%82%B7%E3%82%B9%E3%83%86%E3%83%A0%E8%A9%B3%E7%B4%B0%E4%BB%95%E6%A7%98#j1e8d312), checked2026-10-06, describes recovery classification by own-ink submersion and allied rain, with other states using ordinary recovery. Applying that general rule to Super Jump flight is an inference, not new console footage. Its listed ordinary12.6 HP/s differs from the adopted runtime12.5; this patch deliberately preserves the current coefficient and leaves the numerical calibration separate. The page's submerged per-frame/per-second figures are also not used to change the existing runtime. No full build, browser run or whole-CI acceptance is claimed. Refs #856; #744 charge handling is preserved.

# INKWAVE projectile reconstruction — independent review, 2026-10-11

Review target: working tree on `feat/inkwave-projectile-vfx-1130`, baseline integration commit `3a864f81`. Reviewer inspected the immutable public source, full production adapter composition, new CPU geometry runtime, source audit, source profiles, tests, and browser capture harness. This is an implementation review, not a controlled comparison with a retail Splatoon 3 execution.

Status: **review in progress**. Findings below describe the first landed renderer revision. Fixes and final validation will be recorded explicitly rather than silently deleting the initial reproduction evidence.

## Initial findings

1. **P1 — Standard horizontal Roller never creates the intended liquid bridges.** `runtime/projectile-visuals.mjs::_rollerLinks` treats `fidelityRollerUnitIndex` as a per-glob adjacency index. The twelve native wide-swing globs all have source unit index zero; only the nearest unit has index one. The check `Math.abs(pi-qi)!==1` therefore discards every adjacent main-unit pair. A full composition, actual `Projectiles.fireFlick`, fixed random 0.5, two 60 Hz updates reproduced 13 bodies, 2,028 vertices, and `linkedRollerPairs=0`. Adjacent main heads were approximately 0.265 world units apart, inside the configured bridge interval of 0.18–0.9 at radius 0.3. This is a visible functional omission in the requested connected membrane.

2. **P2 — Coarse native update intervals mislabel history positions.** `recordStep` reads the final `p.prev` after `_step` returns. Native `InkFlightRuntime.stepHead` can execute multiple internal 60 Hz steps and overwrite `prev` on each. A real Shooter with `Projectiles.update(1/30)` recorded history age zero at z=2.565996 instead of its muzzle z=0.3; age 1/60 was z=3.698994 instead of the actual first endpoint z=2.565996; only the final age 2/60 endpoint z=4.831992 was correct. Menu-attract budgeting legitimately supplies coarse intervals. A history derived from the last segment is not a complete authoritative trajectory.

3. **P1 — The proposed long-firing browser performance capture measures a frozen game.** `scripts/check-inkwave-projectile-visuals.mjs::openGameContext` calls `g.debug.freeze()`, but the initial `runFiringPerformance` never unfreezes. Native `Game._loop` returns immediately while frozen. The independent rAF sampler can produce timestamps even while game-frame/projectile/render sample arrays remain empty. The harness initially had no nonzero native frame/shot assertion, so it could label idle measurements as successful long-fire evidence. `runFiringPerformance` also appended its record internally while callers appended the returned record, duplicating desktop and mobile rows.

4. **P2 — CPU geometry is regenerated in fixed ticks and again at the render edge.** The initial adapter calls `projectileVisuals.draw(1)` from the fixed-tick `_draw`, then `syncVisuals(alpha)` from the real render path. A normal 60 Hz frame builds the new mesh twice; a 30 Hz render frame generally builds it three times. The discarded intermediate mesh builds are expensive arithmetic and buffer writes. Draw-call count alone does not expose this cost.

5. **P2 — Explicit transient arrays remain in the new render hot path.** The initial `projectileVisualKind` uses an array literal for Shooter-family membership and `_drawRound` uses another array literal for sphere-kind membership. These should be hoisted or replaced with scalar comparisons; claiming no per-frame allocations from typed-buffer reuse alone is insufficient.

6. **P2 — Some purported production fixtures omit the new final adapter.** `patches/splatoon3/tests/source-fixture.mjs::adaptProduction` and `scripts/weapons-fixture.mjs` initially hard-code the previous adapter chain. A test using `productionComposition:true` does not thereby exercise the new renderer. New subject tests must use the actual shared `adaptBuildSource`, assert the installed visual runtime, or read a native emitted build.

7. **P1 — New Three resource UUIDs perturb the shared gameplay PRNG at startup.** Three's `generateUUID` uses four `Math.random()` calls. New BufferGeometry, MeshPhysicalMaterial and Mesh objects consumed twelve additional draws. A matched native VM fixture with the deterministic stream installed before module load reproduced baseline initialization 128 draws versus new initialization 140 draws; first Shooter seed changed from `0.39488261798396707` to `0.2023443109355867`, and its x launch velocity changed from approximately `-0.02579434` to `-0.00034498`. Resetting the stream after constructor invocation hides this regression. Cosmetic resource construction must isolate its UUID randomness or otherwise preserve the startup stream.

## Follow-up findings and correction evidence

- Renderer revision now records native main-glob ordinals and uses them for standard Roller links. Re-running the actual 13-glob, two-tick reproduction produced **11 links**, 3,744 vertices and 6,912 triangles in one new mesh batch. The nearest glob remains separately unlinked. Initial finding 1 is corrected in the inspected working tree.
- An inner native InkFlight point observer now records every actual fixed integration step. The same `update(1/30)` reproduction records z=0.3 at age zero, z=2.565996 at 1/60 and z=4.831992 at 2/60. Initial finding 2 is corrected for the native Shooter path.
- A subsequent collision issue was found: observing immediately after integration precedes collision truncation. The renderer now overwrites the newest same-age point with final authoritative `p.pos`, so the recorded endpoint does not remain beyond the surface.
- A subsequent wall-drop issue was found: `p.age` freezes during wall-drop while `fidelityWallDrop.frame` advances. The renderer author added a separate visual-age bridge using that sourced phase clock; gameplay age remains unchanged. Independent recheck is pending.
- Initial fixed-tick mesh construction was removed; the new CPU geometry builds at `syncVisuals` on the render edge. Hot-path membership arrays were replaced with scalar comparisons. Initial findings 4/5 are corrected by inspection.
- The renderer initially wrote `_iwVisualGroup` onto authoritative damage ledgers. No whole-ledger packet serialization was found, but own-property state changed. The renderer author moved group identity to a render-owned WeakMap. Clear now resets peer-owner/actor references and render-record references; independent reuse verification is pending.
- The deterministic browser harness directly calls `R.render()`, bypassing the normal main-frame render-edge hook. After deferring CPU generation, the harness must explicitly call `syncVisuals(1)` and assert candidate geometry exists; otherwise skipped legacy heads can produce empty-ink screenshots without failure.
- The developing source/geometry test suite was rerun after the synthetic radius correction: **5/5 passing**. This is still insufficient native integration/browser evidence on its own.

## Evidence and unresolved comparisons

- The new renderer stores world-space positions and normals in actual CPU geometry. Beauty, shadow and override normal/depth passes therefore see the same topology, avoiding the legacy shader-displacement/raw-depth mismatch. Ellipse/taper normals are present; decorative-lobe derivatives and transport-frame curvature are approximated. No extracted Nintendo normal map or material is established.
- Source profiles retain absent values as null, explicit zero as zero, negative offsets and `-1` sentinels. Pinned numerical DrawSizeParam and Splatling tail 3F values do not recover topology, branch connection rules, opacity curves or runtime tail dispatch. Ordinary Shooter/Dualies fallback 2F remains explicitly unsourced.
- Hoian EP02 CPU history stripe implementation and S2 symbol names do not prove those algorithms dispatch for the target S3 weapons. Original target effect binary, emitter set, primitive/texture/shader identity and controlled version-11.3.0 gameplay comparison remain unresolved.
- Catalog emissions use `type:'shot'` across multiple families; classification must use immutable source actor/family/descriptor and must not change when the owner switches weapons. Bubble, spiral, explosive, triple and paired Slosher derivatives require separate modes. Explicit zero-radius companion proxies must stay invisible. Special projectile descriptors must keep their dedicated behavior.
- Radius interpretation needs explicit comparison: the initial new mature Shooter body uses `p.vis` while the old rendered width used `p.vis * 0.7`; the initial new Slosher body uses the sourced helper radius while the old width used helper radius `* 0.5`. Roller source radii remain 0.30/0.36. Preserving a raw source scalar is distinct from preserving the previous physical or projected width.
- Delayed Slosher births resample the muzzle inside the gameplay wrapper; histories must begin there, not at enqueue pose. Ghost owner catch-up can execute multiple steps in one local tick, so history must use projectile age rather than local `G.time`. A remote projectile whose owner clock stops must not repeatedly interpolate its last interval on unrelated local ticks.
- Clear, pool reuse, normal retirement, remote retirement, match transitions and explicit new-backend disposal must release history ownership without retaining actors or connecting consecutive projectile lifetimes. Overflow must only reduce visual detail.
- Native game captures must include matched before/after seeds, camera transforms, actual loaded build identity, nonempty projected ink, wall/floor contact, first four versus rear five separation, and 30/60/120 Hz rendering. Desktop Chromium/SwiftShader and mobile emulation do not establish native Android GPU behavior. Pure history tests do not establish native fixed-clock/render integration or visual parity.

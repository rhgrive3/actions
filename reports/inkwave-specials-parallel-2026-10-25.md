# スペシャル処理の並列最適化と再評価

基準はPR #1876の `6dacd47095352cfd600f9c83012c71a2f298a460`。5つの実装担当で調査し、モデル変更後に新しい担当でコード・oracle・計測方法を独立に見直した。検証はローカル環境で行い、Actionsは起動していない。公開・マージは行わず、同じドラフトPRを更新する。

## 採用した変更

| 対象 | 処理の削減 | 保持した結果 |
| --- | --- | --- |
| トリプルトルネード | 固定20方向を再利用。3本・26パルスのsin/cosは各1446→20回 | 全塗り位置・seed・照会順・塗り加算 |
| デコイチラシ | seedごとの12方向係数を再利用。120Hzの例で各2892→24回 | 狙いと地形は毎回照会。動く足場・再入も検証 |
| メガホン | 既存ビームの一時Vector複製、6台分の展開・旋回・発光の重複を削減 | 所有handle、端点、粒子、乱数、失効時刻 |
| ウルトラショット／キューインキの保持姿勢 | 更新済みsubtreeの行列を読み、4点の再更新を省く | ネイティブIK、姿勢、銃口、手の誤差 |
| 共通の軌跡 | 透明な末尾頂点をtyped arrayのブロックコピーで生成 | 全Float32バイト列、index、upload、handle、寿命 |
| ウルトラショットの弾 | 現在／前回の軌道計算で同じ数値軸の基底を共有。正規化4→2回 | 元の演算順、2回の入力観測、可変軸・独自変換のfallback |

当たり判定、ダメージ、塗り、ゲージ、通信の権限、ゲーム時計、見た目の数・形・寿命は変更しない。既存PR #1870の別の最適化は取り込まず、同じファイルのhunkを照合した。

## 局所CPU計測

Node 24.19.0 / Xeon Platinum 8573C。前後の順序を交互にし、他の重いテストを止めて計測した。各値は以下の限定された処理時間であり、ゲーム全体や端末FPSの改善率ではない。

| 計測条件 | 基準→候補の中央値 | 結果 |
| --- | --- | --- |
| 共通軌跡、4/40本×2/12/48生存点、各3000更新×11回 | 条件ごとの生時間は[ribbon.json](specials-parallel-20261025/ribbon.json) | 6条件で約7〜38%短縮 |
| 両手保持のfit、10000回×9回、実THREEとsolver sink | 13.18→9.11 ms | 約31%短縮 |
| 6台のスピーカー姿勢、10000回×9回 | 9.51→7.55 ms | 約21%短縮 |
| メガホンの既存イベント、30000行×11回 | 86.78→83.04 ms | 約4.3%の小差。大きな速度向上とは認定しない |
| デコイ配置、実生成物を同条件のVMで10000回×9回 | 137.16→75.77 ms | 約45%短縮。VMと接触sinkの局所値 |
| ネイティブ軌道更新、実生成物ESMを同じNode realmで200000回×9回 | 150.00→95.75 ms | 約36%短縮 |

再評価で、メガホンの最初の計測には計数用コードの負荷が混ざっていた。上表は計数なしで測り直した値で、計数は別の非計測fixtureへ分離した。旧値は採用しない。デコイの最初のhost対VM比較も不適切で、同じVM loaderの実生成物同士へ修正した。公開軌道selectorの一時オブジェクトを減らすだけの案は速度の裏付けが弱く不採用とし、selectorを基準版と完全一致に戻した。通常の拘束処理で効果がなかったソケット回転cacheも不採用。

## 最終検証と証跡

最終結果は[validation.json](specials-parallel-20261025/validation.json)、[画面・状態の比較](specials-parallel-20261025/visual-comparison.json)に保存する。本番の通常ビルド、全入力のGit照合、artifactハッシュ、strict quick check、startup budgetを確認する。

- 現モデルでのsource回帰は43件。基底共有の既存ネイティブ回帰は別途85件。
- 最終生成物でworld、director、native orbit、既存の生成物・直接ソース所有を検証する。source抽出や追加minifyを実生成物の代用にしない。
- 同じseed・同じdriverで基準／候補の実ブラウザを起動し、ネイティブの発動・保持・泳ぎ・死亡・失効、3本のトルネード、12個のデコイ、GPU資源の解放を確認する。23枚のPNGを全RGBAで比較し、姿勢・イベント・塗り座標digest・資源数も照合する。
- 比較器自体には、RGBだけの変更、画像欠落、seed／driver／資源の不一致を拒否する負の対照を設けた。
- 既存Crab ribbon fixtureの2件は基準版でも失敗する。PR #1870に必要なfixture修正があり、本変更では複製・緩和・skipしていない。全リポジトリのCIが成功したとの主張ではない。

通常のステージ全体、ライブネットワーク、Safari/iPad、実GPU、Switch実機のFPS・画面一致は未確認。ブラウザの塗りは制御したsinkで、実ステージの塗り性能測定ではない。

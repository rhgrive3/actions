# 全サブ・スペシャルの投擲／着弾／爆破位置予測

対象: `INKWAVE-main-b1f571da-20261016-edit`。基準ソース: `rhgrive3/actions@5d4c27df4d4acb49676c08ca72cfa4486a3c64c2`。調査日: 2026-10-30。

## 結果と比較の範囲

PvPのサブ14種、スペシャル19種を個別に調査し、投擲・射出・接触・設置・連続爆発の予測を、それぞれの実行処理へ接続した。予測専用の共通ボムを飛ばす方式から、武器ごとの実際の初期化・飛翔・接触・導火線を読む方式へ変更した。

この変更で検証する「一致」は、同じ入力・現在の地形・同じ60 Hzのゲーム時計に対する **INKWAVEの予測と実弾の一致** である。Nintendo Switch上の全条件の再現を認定するものではない。公開パラメータで省略されたクラス既定値や、既存の校正値は、抽出済みの値として扱っていない。重要な残差は末尾に列挙する。

参照バージョンはSplatoon 3 Ver.11.3.0。任天堂の[公式更新履歴](https://support.nintendo.com/jp/switch/software_support/av5ja/index.html)で、2026-08-20版のウルトラショット、ウルトラチャクチ等の変更を確認した。数値の個別調査には、ゲームから抽出されたパラメータを第三者が公開する[Leanny/splat3の1130データ](https://github.com/Leanny/splat3/tree/main/data/parameter/1130/weapon)を使用した。これは任天堂が公開したエンジンソースではない。

[サブの個別数値と出典](sub-research.md)、[スペシャルの個別数値と出典](special-research.md)に、初速・重力・空気抵抗・慣性・衝突マスク・時間・省略値をまとめた。サブ14種＋スペシャル19種＋補助参照のガチホコ1種、計34ファイルの内容が各Git blob SHAに一致することを[内容検証記録](evidence/reference-content-verification.json)で確認した。

## 予測する位置を分ける

- **最初の接触点**: `firstImpact`。壁、天井、床などへの最初の有効接触。
- **現在の条件で確定する終点**: `endpoint`。転がり・反射・付着後の爆発・効果の基準位置、または設置／作動位置。ナイスダマの効果位置とダメージ照会に使う中心の差は後述する。
- **複数の爆発点**: `explosions`。タンサンの連爆、ウルトラショットの3弾、デコイの各着地点など。
- **将来の対象や操作に依存する位置**: `targetDependent` と未確定の結果。追尾する相手、動くヤグラ、サメライドの停止操作などを固定された将来の爆心として確定表示しない。

画面のリングは位置を示す印であり、各攻撃のダメージ範囲の輪郭は表さない。予測が地形に接触した場合はその法線を使う。空中や壁の終点を床へ再投影しない。

## 表示・状態の修正

`throw-prediction.mjs` を全武器ランタイムのインストール後に接続した。スペシャルが入力を所有する間は、そのスペシャルの準備状態でガイドを表示する。元のmainがサブ準備中だけを表示対象としていたため、スペシャルでは表示フラグがfalseでも専用予測を照会する。

予測は通常30 Hzで再計算する。武器、ギア、復活、地形インスタンス、特殊状態、チャージ境界、照準や位置の大きな変化では即時に無効化する。静止している場合も再計算し、動く地形や設置物の変化を反映する。表示用の点を再利用し、再計算しないフレームでは頂点バッファを再転送しない。

軌道は既存の有界な描画バッファに収める。単純な等間隔の間引きで壁の反射点を落とすことを避けるため、端点と曲がり角を優先する。ウルトラショットの追加2本は専用バッファを持ち、既存の線マテリアルを共有する。複数地点の印も既存のリング資源を共有する。`clear` 時には追加ノードを外し、専用バッファだけを解放する。

## 予測を呼んでも実ゲームを進めない

予測は弾を生成せず、HP・インク・チャージ・設置物・シーン・乱数・音・塗り・送信記録を更新しない。衝突照会が内部で更新するヤグラ付着位置やクーラーのコライダーも、予測用のコピーへ隔離した。実Characterの放出位置はrigの姿勢を一時評価して取得し、`finally` で各field・bone・行列を復元する。呼び出し前後にlive姿勢の変更を残さないことを検査した。

これは単に副作用関数をstubに置き換えて成功させた検証ではない。実NetMatchの記録が予測では増えず、本当の投擲では増える対照、および実Characterの全ボーン・行列・姿勢が予測前後で一致する検査を含む。

[再現スクリプト](evidence/counterfactual-probe.mjs)と[数値記録](evidence/before-after.json)は、同じAP0、同じ照準、実Level／Physics、実Projectilesで比較したもの。

| 再現 | 修正前 | 修正後 |

センサーには既存の1.8秒という校正された空中期限がある。旧実装の浮動小数点比較では1 tick余分に進む場合があった。共有stepは60 Hz境界でこの期限を終了させる。上表のワールド座標は本家の距離を測定した数値ではない。

## 原作との一致について残る確認事項

1. **公開override JSONの省略値**: サブ複数種の重力・抵抗、共通Z慣性、積分順序、全衝突マスクの内部既定値は、値が省略されていることだけでは決定できない。
2. **キューバンのダメージ中心**: `DamageOffsetY=0.6` は抽出値としてspecに記録されているが、現native爆発のダメージ中心は `b.pos` を使用する。原作の局所軸とこのoffsetの適用は未確認・未実装。今回の予測は、現runtimeで実際に使われる中心に一致する。
3. **ナイスダマの中心**: 予測の終点と今回の比較数値は、接触点と `booyahBlast.pos` が持つ効果の基準位置を表す。既存のダメージ照会はこの位置から `+0.2Y` を使う。抽出値 `DamageOffsetY=-0.2` との座標系の対応は本家未確認であり、推測で符号やスケールを変えていない。
4. **既存校正**: センサーの重力24／空中期限1.8秒、カーリングの補間・減速・接触オフセット、タンサンの一部の転がり・入力加速、ロボットボムとトーピードの探索／追尾の一部は、既存INKWAVEの校正を含む。スペシャルでも、デコイの散開・崖際再配置、クーラーの壁滑り・設置footprint・模型AABB・反発、カニ大砲の初速等には未抽出の既定値や校正がある。これらの予測は現runtimeとの一致であり、原作の内部値として確定したという意味ではない。
5. **将来の移動**: 今後動く敵、付着先のヤグラ、今後の照準／停止／振り入力は、現在の位置から一意に確定できない。予測は現在の世界と既に受付済みの準備／チャージを読む。
6. **検証環境**: CPUによる本番構成の実行、制御地形のブラウザ描画、本家実機比較は別の検証である。Nintendo Switch実機・全ステージ・あらゆる入力履歴での誤差0を、この結果から認定しない。

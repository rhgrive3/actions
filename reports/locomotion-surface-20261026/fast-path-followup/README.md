# 平床支持の詳細追跡を回避（2026-10-26）

直前のmovement headは `6142e49045700b7c8ad70a902f963c1a64fe8c70`。
既存の下り坂修正は、0.05のActor表示離隔がある平床でも、安価な高さ判定より先に
衝突面の収集・sort・確認rayを実行していた。

`rollerDrumSupport` の既存高さ判定を先へ移し、不成立の場合だけ既存の連続面追跡を実行する。
支持の二つの述語・0.075許容・grounded/hit条件・壁判定・塗りの連続性判定は無変更。
両判定はORであり、移動・インク・ダメージ・塗りの許可条件を新たに追加していない。
下り坂は高さ差で安価な判定が不成立となり、従来どおり連続面追跡へ進む。

新規回帰は実Level/Physicsを使う。平床では確認ray0、空間問い合わせは広域＋高さ列の2回、
連続追跡用scratch未生成を検証。下り坂では確認ray1を要求し、崖と空中は未支持を維持する。
別の同高床へ中心線の隙間を跨ぐケースは、以前からの安価な支持fallback自体は成立するが、
塗りは独立した実衝突面の連続性判定で拒否される。この区別も回帰で保持した。

- 影響するソース4ファイルの回帰: **20成功、失敗0、skip0**。
  新規5件、既存の下り坂実Actor30/60/120Hz 3件、床離隔2件、#847の10件。
- 実塗り境界だけの選択実行: **5成功**。
  全追加ローラー／フデの上下45度、崖、平行な別床、native三角形の穴、狭い隙間を検証。
- 最適化ビルドの新規回帰: **5成功、失敗0、skip0**。
- 直前headの `roller.mjs` を戻す負対照: **2成功・3失敗**。
  平床で詳細追跡をしてしまうカウンター条件が失敗する。元のassertionは緩和していない。
- #847の入力pinは変更後の完全なファイルSHA256へ更新。既存の厳格な逆変換が、
  本修正を含む現在ソースから以前の固定ソースをbyte単位で復元することも10件内で検証した。

4,096回の平床支持の短い測定では、確認rayが4,096→0、空間問い合わせが12,288→8,192、
追跡用scratch生成があり→なし。単独実行の時間は60.75ms→45.74msだったが、共有ホストの
別実行では80.66msとなるため時間差を性能保証として扱わない。カウンター削減を検査基準とする。

全ログは元バイト列をgzip保存し、raw/gzip両方のSHA256をvalidation.jsonへ記録。
新しいブラウザ・実機・音声・原作映像比較は行っていない。前回完了した移動テスト全体は再実行せず、
この順序変更に関係する範囲のみを実行した。workflow変更・PR・merge・手動CIなし。

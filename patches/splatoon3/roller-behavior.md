# ローラーの振りと公開版パッチ

対象は `inkwave-public/` に適用する独立パッチ。数値基準はスプラトゥーン3 11.3.0 のスプラローラー、ギア補正なし。公開版本体は変更しない。

## 根拠と未確認境界

- [任天堂のローラー解説](https://www.nintendo.com/jp/character/splatoon/fashion/index.html) は、ジャンプ中の攻撃がタテ振りとなり、ヨコ振りより左右が狭く前方へ長く塗れることを説明している。紹介映像 `js-media-roller-2` / `js-media-roller-3` は横と縦の軌道を示す。縦ではドラムの幅方向が縦向きになり、頭上から振り下ろす。映像の版、正確なブキ、ギア、入力のフレームは未特定で、入力や発生時間の測定資料としては使わない。
- `reference/curated-numbers.json` の固定コミット `7280ff9cde8bb1c5dcef46c700c326471584d2e6` にある `WeaponRollerNormal.game__GameParameterTable.json` は横 `WeaponWideSwingParam/SwingFrame=21`、縦 `WeaponVerticalSwingParam/SwingFrame=26`、両方 `InkConsume=0.085`、回復停止43F/58Fを含む。既存 profile の秒・タンクポイント換算を維持する。抽出データの意味や物理スケールの実機検証は別の課題。
- 既存 profile の横42F / 縦47Fの開始間隔は校正値。資料にない完全な硬直・入力予約仕様を確定扱いしない。ZR後に遅れてジャンプする場合の振り変更の受付境界も一次資料で確認できていない。現状は攻撃開始時の空中状態で選択し、その後のジャンプでモードを変えない。
- 原作の塗り形状、弾の各グループの発生位置、当たり判定、複数弾の威力集約、地形・通信条件までの完全一致は未確認。既存の縦5弾・横12弾、距離別威力、重力・抵抗・塗りを引き続き使う。この変更をそれらの解消証拠にしない。

## 最初の差分と変更

`Character._poseFlick` は固定の約0.22秒で振り抜き、ローラーのヨコ/タテを区別していなかった。武器ドラムも0.15秒で回転の勢いを加えていた。実際の放出21F/26Fとずれるため、放出前に振り終わったように見えた。

`runtime/roller.mjs` は既存 WeaponRunner の振りを利用し、開始した攻撃の種類・発生・開始間隔・経過時間を Character と共有する。ヨコ振りは元の関節曲線を実際の発生時刻に合わせる。タテ振りは元の二腕IKを使い、柄を持つ手のアンカーを頭上へ引き、ドラムを縦向きにしてから前方へ振り下ろし、持ち姿勢へ戻す。関節角度、振りかぶりの割合、フォロースルーの曲線は公式映像を参考にした校正であり、原作の抽出されたアニメーションではない。

放出と武器回転は同じ経過時間を使う。Float32の表示用タイマーへの書き戻しで横の回転が1F遅れないよう、武器の経過時間を共有状態から直接読む。固定0.7秒のモーション上限も、その攻撃の開始間隔に置き換える。着地は攻撃モードや経過時間をリセットしないため、着地の吸収姿勢と縦振りが重なる。

実表示の確認で、縦向きのドラムの回復中に下端が床を横切る差分を発見した。フォロースルー時のアンカーを持ち上げ、実ジオメトリの境界で着地後の回復中に床を貫通しない回帰を加えた。既存ヨコ振りのフォロースルーで床に触れる軌道、斜面・段差での武器と床の関係は別途未確認。

転がし中に新しい振りを始めると、ドラムを地面から離す。その時に残っていた `rolling=true` を解除する。押し続ければ既存の転がし条件で再開し、離せば止まる。実行時の小さな浮動小数点誤差で21F/26Fの放出が1F後になる場合も補正する。

## 実装と再現

`adapter.mjs` は、ビルド先の Character が持つ実際の定数を `CHARACTER_CHANNELS` と `CHARACTER_TIMERS` で公開する。私有配列のオフセットを独立パッチに複製しない。Character と武器アニメーションの元ファイルは `upstream-lock.json` のハッシュで固定し、接続点の欠落や重複はビルドを止める。

- ジャンプと射撃を同時に押す: Actor のジャンプ処理後に縦振りを開始する。
- 空中で開始し、放出前に着地する: 種類を保持し、26Fで縦の弾を出す。
- 地上で開始し、その後ジャンプする: 開始時の横を保持する。次の攻撃で再選択する。原作の早いジャンプ変更境界は未確認。
- 転がしから射撃を押し直す: 振りかぶり中の転がし状態を解除する。射撃を保持すると既存条件に従い転がしに戻る。
- インク不足、ブキ変更、リセット: 存在しない攻撃のモーションを作らず、状態を破棄する。

## 検証

`node --experimental-vm-modules --test patches/splatoon3/tests/roller.test.mjs` は実 Actor、実 WeaponRunner、実 Character の手足・武器ジオメトリを通す。横21F/縦26F、60Hz/120Hz、同時入力、着地、押し離し、次の振り、インク不足、骨と武器の移動、放出に同期したドラム回転、ハッシュと接続点を確認する。

ブラウザの証拠と公式映像は、作業の永続 evidence ディレクトリ `inkwave-walk-20261002/roller/` に保存する。Nodeの骨測定、Chromiumでの表示、原作の実機比較は別の証拠であり、ChromiumだけでiOSや原作実機の完全一致を主張しない。

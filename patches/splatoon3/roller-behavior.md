# ローラーの振りと公開版パッチ

対象は `inkwave-public/` に適用する独立パッチ。数値基準はスプラトゥーン3 11.3.0 のスプラローラー、ギア補正なし。公開版本体は変更しない。

## 根拠と未確認境界

- [任天堂のローラー解説](https://www.nintendo.com/jp/character/splatoon/fashion/index.html) は、ジャンプ中の攻撃がタテ振りとなり、ヨコ振りより左右が狭く前方へ長く塗れることを説明している。紹介映像 `js-media-roller-2` / `js-media-roller-3` は横と縦の振り平面を示す。今回取得したスプラローラー名付きの `js-media-roller-4` もジャンプ中の縦振りと次の振りを示す。ドラムが縦の平面で立つ・前後へ向く動きは見えるが、射出時のインク遮蔽とカメラのため、原作の一定world軸や正確な90度回転は復元できない。映像の版、ギア、入力のフレームは未特定で、発生時間の測定資料には使わない。
- `reference/curated-numbers.json` の固定コミット `7280ff9cde8bb1c5dcef46c700c326471584d2e6` にある `WeaponRollerNormal.game__GameParameterTable.json` は横 `WeaponWideSwingParam/SwingFrame=21`、縦 `WeaponVerticalSwingParam/SwingFrame=26`、両方 `InkConsume=0.085`、回復停止43F/58Fを含む。既存 profile の秒・タンクポイント換算を維持する。抽出データの意味や物理スケールの実機検証は別の課題。
- 既存 profile の横42F / 縦47Fの開始間隔は校正値。資料にない完全な硬直・入力予約仕様を確定扱いしない。ZR後に遅れてジャンプする場合の振り変更の受付境界も一次資料で確認できていない。現状は攻撃開始時の空中状態で選択し、その後のジャンプでモードを変えない。
- 原作の塗り形状、弾の各グループの発生位置、当たり判定、複数弾の威力集約、地形・通信条件までの完全一致は未確認。既存の縦5弾・横12弾、距離別威力、重力・抵抗・塗りを引き続き使う。この変更をそれらの解消証拠にしない。

## 最初の差分と変更

`Character._poseFlick` は固定の約0.22秒で振り抜き、ローラーのヨコ/タテを区別していなかった。武器ドラムも0.15秒で回転の勢いを加えていた。実際の放出21F/26Fとずれるため、放出前に振り終わったように見えた。

`runtime/roller.mjs` は既存 WeaponRunner の振りを利用し、開始した攻撃の種類・発生・開始間隔・経過時間を Character と共有する。ヨコ振りは元の関節曲線を実際の発生時刻に合わせる。タテ振りは元の二腕IKを使い、柄を持つ手のアンカーを頭上へ引き、ドラムを縦向きにしてから前方へ振り下ろし、持ち姿勢へ戻す。関節角度、振りかぶりの割合、フォロースルーの曲線は公式映像を参考にした校正であり、原作の抽出されたアニメーションではない。

放出と武器回転は同じ経過時間を使う。Float32の表示用タイマーへの書き戻しで横の回転が1F遅れないよう、武器の経過時間を共有状態から直接読む。固定0.7秒のモーション上限も、その攻撃の開始間隔に置き換える。着地は攻撃モードや経過時間をリセットしないため、着地の吸収姿勢と縦振りが重なる。

従来の着地後・射撃を保持しない2m/s回復では、傾いたドラムの境界箱が床下でも、実描画頂点は床上だった。境界箱だけを床貫通の証拠にしない。今回の射撃保持・転がし再開条件では実頂点も床下になる別の問題を確認し、握りアンカーと回復ブレンドを調整した。斜面・段差での武器と床の関係は別途未確認。

転がし中に新しい振りを始めると、ドラムを地面から離す。その時に残っていた `rolling=true` を解除する。押し続ければ既存の転がし条件で再開し、離せば止まる。実行時の小さな浮動小数点誤差で21F/26Fの放出が1F後になる場合も補正する。

## 2026-10-02 の追加比較と洗練

[詳細な比較記録](reference/roller-motion-comparison-2026-10-02.md)では任天堂サイトの映像を再取得し、最大解像度1920×1080・60fpsの版を使用した。転がし紹介映像は通常型の見た目と推定できるため、待機、横振り、押し続けた転がし、離した後の持ち上げを比較した。別にスプラローラー欄の名付き動画を追加取得し、ジャンプ縦振り、着地、次の縦振りを確認した。横振り専用映像は大型ドラム、縦振り専用映像は変形する長いドラムで、別ブキの外観と推定できる。これらの発生時間をスプラローラーの21F/26Fへ流用しない。

従来の床近くの前方待機から、肩の後ろへ持ち上げる構えへ変更した。横振りは構えからドラムを横向きに振りかぶり、縦振りは頭上から下ろす。アンカーと曲線はINKWAVEの異なる体格・柄の長さ・腕の可動域に合わせた校正であり、任天堂の関節座標ではない。腕が前方の握りに届かなかった振り抜き姿勢も調整した。武器だけを後からワールド座標で移動せず、既存の右手アンカーと左手の握りIKを通す。

転がしへの復帰はCharacterの固定0.6秒条件を使わず、実際のWeaponRunnerの `rolling` を使う。回復中に転がしが再開すれば、同じ状態に沿って両腕とドラムを下ろす。離したときは持ち上げ、新しい振りでは地面から離れる。ジャンプ、着地、ダンス、サブ、スーパージャンプ等の既存レイヤーは引き続き合成する。リセットとブキ変更では旧0.7秒の振りや0.15秒の武器回転が代わりに走らないよう、表示用の振りタイマーも取り消す。既に放出した回転の自然な減衰まで巻き戻す処理ではない。

## 実装と再現

`adapter.mjs` は、ビルド先の Character が持つ実際の定数を `CHARACTER_CHANNELS` と `CHARACTER_TIMERS` で公開する。私有配列のオフセットを独立パッチに複製しない。Character と武器アニメーションの元ファイルは `upstream-lock.json` のハッシュで固定し、接続点の欠落や重複はビルドを止める。

- ジャンプと射撃を同時に押す: Actor のジャンプ処理後に縦振りを開始する。
- 空中で開始し、放出前に着地する: 種類を保持し、26Fで縦の弾を出す。
- 地上で開始し、その後ジャンプする: 開始時の横を保持する。次の攻撃で再選択する。原作の早いジャンプ変更境界は未確認。
- 転がしから射撃を押し直す: 振りかぶり中の転がし状態を解除する。射撃を保持すると既存条件に従い転がしに戻る。
- インク不足、ブキ変更、リセット: 存在しない攻撃のモーションを作らず、状態を破棄する。

## 検証

`node --experimental-vm-modules --test patches/splatoon3/tests/roller.test.mjs` は実 Actor、実 WeaponRunner、実 Character の手足・武器ジオメトリを通す。横21F/縦26F、30Hz/60Hz/120Hz、同時入力、20F/40Fでの着地、2m/s移動、profileの7.92m/s転がし、押し離しと押し直し、次の振り、インク不足、リセット、変形、両手の握り、放出に同期したドラム回転、ハッシュと接続点を確認する。30Hzでは21Fの時刻を挟む最初の更新で放出し、26Fは13更新で放出する。これを30Hzでも21回更新する仕様とはしない。

旧証拠は `inkwave-walk-20261002/roller/` に保持する。今回の公式映像、フレーム順、前後のブラウザ、実頂点測定コードと結果は永続 evidence ディレクトリ `inkwave-motion-compare-20261002/roller/` に保存する。ブラウザは制御した平面・水平照準・三四分視点の描画であり、原作のFOV、入力、ギア、体格を完全に再現した計測ではない。Nodeの骨測定、Chromiumでの表示、原作の実機比較は別の証拠であり、ChromiumだけでiOSや原作実機の完全一致を主張しない。

# Supported shooter carry

Nintendo's [shooter footage](https://www.nintendo.com/jp/character/splatoon/fashion/index.html), media `y7Zl26Zl12n`, lowers the shooter into a two-hand hold after firing. The inspected decoded frames 612–660 have PTS 12.269833–13.069833 seconds, relative clip time 10.2–11.0 seconds. The recording version, inputs, gear, complete idle cycle and joint curves are unknown. The patch profile's 11.3.0 target does not date the clip.

The public Character has `HOLD.shooter.twoCarry=0`. Its support hand therefore separates on release and quiet walking. `carry-motion.mjs` supplies `twoCarry=1` only during the existing shooter's native weapon-pose calculation and restores the shared original hold in `finally`. The native shoulder adjustment, two-bone solver, foregrip and later action layers remain authoritative. The support is continuous across idle, walking, firing and release; sub/throw/fidget/special poses retain their later hand-detachment layers. Other weapon kinds and gameplay are unchanged.

This is an observed hold-policy correction using INKWAVE's native rig; it is not an extracted Nintendo angle or timing. The focused test uses the complete production installer, real Actor/Runner, actual native foregrip/world bone positions and reported native IK. It reproduces a baseline gap over 0.2 rig units, requires the supported gap below 0.015 through 240 transition frames, and checks sub detachment, source-hold identity, reset/dispose and duplicate-realm installation. The contact tolerances are engine regression bounds, not Nintendo dimensions. Physics/original image parity and actual GPU appearance are separate checks.

# Isolated character-asset QA

This is a development fixture, not a character replacement. No production module, build adapter, cache/deployment list or source character asset changes. It loads the actual content-addressed built INKWAVE Character and Three r186, then renders separate static-asset probes. The existing Character animation, weapons and collision authority are not replaced.

## Asset privacy and the default CI case

CI uses only a small mathematical ribbon and three 2x2 maps generated by `synthetic.mjs`. They are original test data, independent of any user image, character or reference. No adopted character GLB, original texture, reference picture, private URL or credential is committed or uploaded. Passing this neutral fixture validates the loader and QA path; it does **not** validate the adopted character's appearance, hair color/material, rig, gameplay or rights for redistribution.

A separate, unpublished local candidate can use the exact same fixture with explicit `--asset` and `--sha256` arguments. Its screenshots may contain private artwork. Keep that evidence local until publication is authorized. There is deliberately no workflow input for an arbitrary asset URL/upload and no automatic upload of local candidate files.

## Run

CI pins official dependencies to esbuild 0.28.2, Playwright 1.62.1 and Three.js 0.186.0. The GLTFLoader/addons come from that official npm package, while the imported `three` core comes from the actual game build. Both must be r186. The old modeler's r159 preview is not used.

```sh
npm install --no-save --no-package-lock esbuild@0.28.2 playwright@1.62.1 three@0.186.0
npx playwright install --with-deps chromium
node --test tools/character-asset-qa/test.mjs
node scripts/build-inkwave.mjs inkwave-public _site
node scripts/check-inkwave-startup-budget.mjs _site
node tools/character-asset-qa/run.mjs --site _site --out .qa-evidence/character-asset --synthetic
```

For authorized private local validation, substitute:

```sh
node tools/character-asset-qa/run.mjs --site /existing/verified/_site --out /private/evidence \
  --asset /private/candidate.glb --sha256 ACTUAL_64_CHARACTER_SHA256
```

`--inspect-only` checks the binary and existing build identity without starting a server/browser. It is useful in restricted environments and is explicitly reported as no browser run. `--three-root` can select an already installed official package. `PLAYWRIGHT_MODULE` and `CHROMIUM_EXECUTABLE` can select supported existing installations; these options must not be used to bypass a denied browser action or security restriction. No new local build copy is necessary when `_site` already exists.

## Gates and evidence

- Immutable GLB SHA; exact chunk lengths, bounds, finite positions, valid indices, UVs and image references. The initial profile is one mesh, static, embedded PNG/JPEG, no external image/buffer URI, skin, morph or animation. This narrow scope fails closed rather than pretending to validate arbitrary characters.
- Build content hash and every manifest artifact are checked. The local server only serves manifest-listed build files and allowlisted QA inputs; it blocks directory traversal, symlinks outside roots and external browser requests.
- An actual 87-bone built Character must produce visible pixels. All 1/8 cases contain 1/8 existing native Characters plus 1/8 separate asset probes. The probes are normalized onto a viewing stage; their presentation scaling is not an authored gameplay scale or head attachment.
- GLTFLoader must decode the actual texture images, both UV sets and MeshPhysicalMaterial. Base/emissive use sRGB; clearcoat is linear. Both map UV channel and texture dimensions are checked.
- Exactly 24 rendered cases: 1/8 copies × day/shade lighting × front/65°/back views × shadows off/on. Every case must change actual framebuffer pixels when the asset probes are hidden. Screenshots and draw/triangle counts are recorded.
- Tone mapping is the game's NeutralToneMapping, exposure .94, sRGB output, fixed 640×480 CSS/device pixels. Lighting is a controlled fixture, not a claim to reproduce every game stage.
- Twelve measured render samples per case after warm-up; `gl.finish()` bounds completion. p50/p95 are software-renderer fixture diagnostics, not mobile hardware FPS or full gameplay performance.
- Ten fresh parse/dispose cycles alternate 1/8 copies. Shared asset geometries/materials/textures are disposed exactly once per parse, ImageBitmaps closed, clones removed, and post-warm-up retained geometry/texture counts must not drift.
- The artifact includes JSON and 24 screenshots. GPU shader compilation, image decoding and resource lifetime require the browser job; Node tests alone are not an acceptance substitute.

## Still outside scope

No real character activation, skin weighting, bone retarget, hair spring chains, face/blink/morph compatibility, weapon socket changes, movement equivalence or Splatoon 3 behavior claim. These remain separate full-asset/game integration gates. Source texture provenance and permission for any newly published derived asset must be established separately; an exported GLB is not evidence of a distribution license.

# MAP3 独立レビュー

対象: Tidewater Plaza / Kelpline Terminal の設計用データ。実ゲームの差替え、ネイティブ移植地形、ゲームソース変更は対象外。

レビューの結論は、**旧案の「広い基底床へ高架を追加する」構成から、床そのものの幅・高さ・接続を作り直す方向へ明確に進んだ**というもの。ただし、単純な矩形の組合せ、中央付近の高所からの圧力、落下時のカメラとbot経路、目標オブジェクトの実装には未確認事項がある。独立静的検査は後述の限定条件で成立しており、対戦の公平性や操作感を保証する結果ではない。

## 確認したもの

- リポジトリの `AGENTS.md`。比較対象を `inkwave-public/` とし、ロジック単独・実ブラウザ・本家実機の検査を区別する指示を確認した。追加の上位AGENTS.mdは確認したパスには存在しなかった。
- `tidewater_design.py`、`kelpline_design.py`、`geometry.py`、担当者の `source-audit.md`。独立検算は `geometry.py` または公開ゲームのモジュールをimportせず、設計データのbuilderだけを読み込んだ。
- 旧 `map2/tidewater-map2.png` と `map2/kelpline-map2.png` の実画素。日本語見出し・凡例は未対応フォントによる四角表示があるため文字資料には使わず、図形構成だけを確認した。旧図は最終成果物へ転載しない方針と整合する。
- 独立チェックの再現スクリプト: `independent_validate.py`。結果: `independent-checks.json`。実際に読んだ各builderのSHA-256を結果へ記録する。

## 独立した静的チェック

### 目標の足場と高さ帯

独立コードで、各スポーン、ホコ初期位置、チェックポイント、ゴール、アサリかご・配置点に、設計用の半径0.675 / 高さ1.6 WUの立位を置いた。中心・内周・外周の計97点で足支持と縦方向の体積重なりを調べ、今回のモデルでは問題を検出しなかった。これは実オブジェクトの全形状、投擲・得点判定、実プレイヤーの全姿勢を確認した結果ではない。

エリア矩形は床と障害物の境界で分割して調べた。Tidewaterの64 WU²、Kelplineの48 WU²ずつの2面は、設定された高さに全域の床があり、地上障害物の面積占有と別の実体上面の正の面積重複はともに0だった。境界線だけ接する橋・遮蔽は「別階の面積」として数えていない。現設計は目標を橋の投影から外しているため、全階が同じエリアへ集計される実装上の問題を避ける配置になっている。ただし実装時にはy/heightToleranceとの対応を保持し、後で橋下へ目標を移した場合は再検査する。

### 床の重なり・頭上空間・カメラ

床同士と坂同士の正の投影重複を、矩形の交差と線形高さの端点で独立に調べた。同一高さの二重床や、面が途中で交差する重複は検出しなかった。重なる床の最小公称空間はTidewater 4.2 WU、Kelpline 3.0 WUだった。

source-auditに記録された通常ヒトpivotの足元+1.85、probe半径0.62を単純に上向きへ足すと、静止時の参考余裕はTidewater 1.73、Kelpline 0.53 WUとなる。この算術は実カメラの全姿勢・boom・レンズ・壁際補正を模擬していない。特にKelplineでは、足元が1.15 WU上がるだけで通常pivotの高さが3.0 WUへ達する。ジャンプや坂際の天井への入り込みは、身体が収まるという静的合格からは除外できない。

### 代表的な直線視線

各マップ5地点を視点にし、床から+1.4 WUの位置同士を結んだ。床・壁・箱・線形の坂スラブには凸体の線分交差を使い、カナアミはこの検査では遮蔽としない。対象点はスポーン中心、中央、主入口、下層出口などに限定した。これはゼロ幅の直線が通るかを確認する証拠例であり、視界面積の網羅検査、弾道、射程、散弾、遮蔽での身体露出、移動目標への命中率ではない。

| 代表視点 | 観測された幾何学的性質 | 設計上の読み |
|---|---|---|
| Tidewater市場ホール | 中央への代表線は地形に遮られる一方、主入口や反対側の橋端への一部線は通る | 「上にいるから中央全部を見下ろせる」という単純な高台ではない。高所内で位置を変える価値がある |
| Tidewater橋端 `[-10,4.8,-3]` | 中央への線長11.49 WU、両主入口、相手側橋端への線長20.88 WUは遮蔽なし | 中央の保持へ強く関与する地点。橋端の占有に対して低路地・横方向・相手高所から対抗できるか実対戦で確認 |
| Tidewater低街路 | 中央へ向かう一部線は通るが、上部床に遮られる方向もある | 下層が完全な安全トンネルではない。入口だけでなく出口での露出を評価する |
| Kelpline高架 | 上部中央目標へ線長46.11 WUの線が通る | 距離が長いので全ブキ共通の攻撃高台とは扱わない。射程と交戦状態を合わせた評価が必要 |
| Kelpline乗場・中央橋 | 高い目標・相手乗場へ通る代表線がある一方、下層への代表線は上面が遮る | 上層支配と下層支配の分担が形状として現れている。上下の味方連携が実際に成立するかは未検証 |

初回検査ではTidewaterの選択した5地点すべてから両スポーン中心への長い直線が通った。設計担当が前方スクリーンと左右の通行余地を追加した後、同じ10本を再検査し、すべて遮られることを確認した。長い線の長さから実射程内の攻撃を断定したわけではなく、今回解消したのも**選択した中心点への直線**である。スポーン全域、左右の出口、空中の発射位置、無敵領域を一括して保護済みとはしない。

## 非対称な体験と公平性

両案はA側を180度回転した地形・遮蔽をB側へ持つ。Tidewaterの西市場と東展望面、Kelplineの高い外周と低い貨物側は、片側の陣営がもう片側より有利という非対称ではなく、各チームの進行方向に対して異なる役割を持つ左右の選択である。この構成は単調な左右反転の3本廊下を避ける点で良い。

一方、幾何の対応は対戦バランスの証明にならない。高所の露出時間、塗り返し、先行して中央へ到達した側の保持、カメラ、視認しやすい背景、目標ルート、bot行動、編成の違いを含めて検証する必要がある。「回転対応あり」「名目経路が両陣営に存在」を、勝率が均衡するという表現へ広げない。

## 分岐・再合流・経路長の読み方

Tidewaterの低街路は下段広場からの分岐であり、スポーンから独立した別のフル経路ではない。市場経路は高い橋端で終わり、中央へ移るには別の降下または下り経路を使う。Kelplineでも高架は乗場へ合流し、低い側路は下層中央へ到達する。名前の付いた折線の本数を、そのまま同じ目的へ到達する独立経路数として数えない。

独立JSONでは各折線の開始点、終了点、3D距離、スポーン始点か、ホコ初期位置が終点かを列挙した。違う始終点の距離を並べて「同じ初動時間」「各ルートが同じ長さ」と評価しない。実移動では坂・旋回・インク・加速・泳ぎ・跳躍・落下が影響するため、折線長を速度で割っただけの値も実測時間ではない。

`geometry.py` の接触辺グラフは、床の間に名目的な継ぎ目があることを確認する。一枚の床の内部が障害物で分断されていないこと、すべての場所から任意の出口へ移動できることを単独で証明しない。折線の半径付きサンプルは明示した折線の助けになるが、床全域の自由な走行や実ゲームのnavを証明するものではない。

## 証拠表現の確認

`reference-observations.md` は、4つの本家ステージの画像を実際に視認したことと、動画全編・隠れた接続・正確な高さ・移動時間を観測していないことを分けている。本家画像からWU寸法や公式面積を逆算していない点は適切。MAP3の独自寸法も公式仕様として説明していない。

このレビューも、名目設計上の通行、独立した静的幾何、実ゲームの操作、本家との実機比較を分離する。新しい地形が見た目と測定指標の両方で旧案から改善していることは説明できるが、実戦の均衡や本家と同等の操作感は未確認として残る。

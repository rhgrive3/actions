# Kelpline Terminal — ずれた船溜まりと乗換デッキ

これは隔離した設計案であり、公開版・ネイティブ移植ステージの変更ではない。座標の正本は [`kelpline_design.py`](kelpline_design.py) の `build()`。図、面積、接続図、ブロックアウトには同じ戻り値を使う。ここでいう WU はゲーム内座標で、実世界のメートルとの較正はない。

## 何を作り直したか

map2 の Kelpline は下層 10,152 WU² が全て y=0、上層 2,296 WU² が y=3.2 であった。壁を増やして平面上の曲がり角を作っても、二つの高さしか持たない地形そのものは変わらなかった。本案では荷役場、乗船口、水際のサービス岸壁、上の乗換回廊を異なる高さの床として作り、低い道と高い道が交差する場所を実際の通路にする。

中央の乗換橋は y=3.6、その下は y=0 のサービス街路。両陣の側面には y=6 の高いガントリーがあり、y=1.2 の岸壁の上を通る。対する別側面は y=2.4 の荷役場から y=1.2 のフェリー指状岸壁を経て低い中央へ向かう。左右は同じ高さ・同じ幅の並列レーンにしていない。地形・遮蔽物・ルール候補は 180 度回転で陣営交換に対応する。

## 高さの役割

| 高さ | 実際に滞在できる床 | 攻防・移動上の役割 |
|---:|---|---|
| 0 | 中央下層、サービス街路、降下着地広場 | 上層から遮られた移動と中央の側面進入。局所の復帰坂から上層へ戻る。 |
| 1.2 | ガントリー下の岸壁、外周坂の下端、フェリー桟橋 | 水際で横に回り込む中継点。ガントリー下と屋外の桟橋では頭上条件が違う。 |
| 2.4 | 荷役場とその取り付き | 中央上層へ横から合流するか、フェリー側へ下りるかを選ぶ大きい床。 |
| 3.6 | 乗船前庭、乗換橋、左右の乗船バルコニー | 上層の主要交戦面。橋の中央は実床、金網は別区画として置換する。 |
| 4.8 | スポーン前の公共コンコース | 主経路と荷役場への分岐、後方のルール目標。全面を横切る段状帯ではない。 |
| 6 | 出発テラス、外周の上側踊り場、乗換ガントリー | 自陣側の高い移動選択肢。前方では低い岸壁に実際に重なる。 |

遮蔽物の上面や坂の途中はこの六高度に数えていない。水平床の最大比率は y=3.6 の約 26.98%。y=4.8 は約 9.78% で、階段一段や小さい箱ではなく両陣のコンコースとして存在する。正確な面積は生成される監査 JSON を正とする。

## 規模と測り方

境界は X=-44..44、Z=-72..72、外接面積 12,672 WU²。スポーン中心は `(0,6,-68)` と `(0,6,68)`、距離 136 WU。同一方法で確認したネイティブ 23 ステージの設定外接面積中央値 12,480 WU² とスポーン距離中央値約 134.16 WU に対して、それぞれ約 +1.54%、+1.37%。これらは外接範囲・開始点の比較であり、実塗り面積が同等という意味ではない。出典と方法は [`source-audit.md`](source-audit.md) と [`baseline-metrics.json`](baseline-metrics.json)。

この版の隔離座標計算では、遮蔽物の占有を引いた床・坂の水平投影和集合 8,887.2 WU²、上下を別面として足した水平投影 11,095.2 WU²、上下が通路として重なる XZ 面積 2,208 WU²。全境界を埋めて面積を得ず、船溜まりと岸壁の切れ目を残した。この設計専用の控除後面積をネイティブの生の衝突面と直接比較しない。別途、双方で上向き面・遮蔽物上面・埋まった面を含め、設定範囲で切り、0.25 WU格子を使う同一方法の比較では、Kelpline案のXZ和集合は9,032 WU²、ネイティブ23ステージ中央値は8,037.125 WU²（約+12.38%）。同じ実塗り面積や到達可能面積を示す値ではない。詳しくは `proposal-common-metrics.json` を参照。

## 上下接続と水際

22 本の坂を両陣の対応で生成する。主スポーン坂は幅 16、主前庭坂も幅 16。水際の外周坂は幅 6、落差 4.8、走行方向の長さ 16、勾配 30%。乗船バルコニーへの局所復帰坂は幅 8、落差 3.6、長さ 8、最大勾配 45%。最小の必須接続はフェリーから低い中央へ渡る幅 4 の坂である。実際の squid 地形半径 0.675 WU を両側から引くと、幅 4 の通路で中心が動ける幅は 2.65 WU。これらは静的設計値で、実 Actor の接地・坂端・壁際挙動を保証しない。

中央橋の下面 y=3.0 と下層 y=0 の間に 3.0 WU、ガントリー下面 y=5.4 と岸壁 y=1.2 の間に 4.2 WU を確保した。高い回廊からコンコースへ渡る横坂の下も最小 3.0 WU。必要な坂の場所には下の地形を残していない。段丘の境目に同じ高さの大床を重ねる処理もない。実描画・衝突へ変換する際の坂下端厚みや共有面処理は別の実装課題である。

`A_boarding_drop` は x=-30 のバルコニー端から西へ出て、下層の x=-31.5、z=-21 に着地する。真下の床を貫通する指示ではない。戻りは `A_recovery` の約 28.27 WU。金網は既存の復帰坂の近く、バルコニーの X=-30..-22、Z=-28..-22 に置く。金網の `(−26,3.6,−25)` から真下のサービス街路に落ち、`A_grate_recovery` の約 37.77 WU で上へ戻れる。中央の目標橋は全面を実床にし、目標取得のために金網を必須にしない。金網とその下の床は別の床で、金網直下の遮蔽物は置かない。落下硬直・慣性・カメラ・敵の待ち伏せを含めた実際の復帰性能は未検証。

外周坂と高い出発テラスには水際がある。公開版に向けた詳細化では縁の視認性と必要箇所の非塗装ガードを作る必要がある。本座標にはその全てのガード衝突を仮に存在するものとして計上していない。

## 経路とルール候補

主経路、外側の高い経路、外側の低い経路、荷役場・フェリー経路を、実際の床と坂を連続するポリラインで示した。対応する両陣の全経路は同じ距離になる。記載した経路は互いに完全独立の四レーンではなく、出発テラスや乗船前庭で分岐・合流する。静的な接続グラフでは全 64 床・坂が一つの成分になる。

エリア候補は中央橋の両側の下層、幅 6×長さ 8 の二つの帯であり、上層の直下を避ける。ホコ初期位置は中央上層の実床。ホコ・アサリの後方目標は y=4.8 のコンコース。ヤグラは y=3.6 の乗船デッキから実床の橋を通り反対側へ進む。共有検査器のヤグラ専用検査は、ソース上の床・柱と回転時の隅を含む静的サンプルであり、具体的な形状・サンプル条件は生成監査を正とする。2.5 WU の経路設計余白も確保する。実ゲームの搭乗者・チェックポイント・最高床選択・フレーム間の連続掃引は未確認である。

塗りはソース上で各面を区別している。一方ミニマップは同じ XZ の最高面を中心に表すため、この上下通路を正しく説明する UI は未完成。エリアを将来上下に重ねる場合、既定の高さ許容が無限大であるため、高さ帯を明示して判定する必要がある。この案で動作互換を確認済みとはしない。

## 確認した範囲と残る検証

共有の静的検査では、全経路を最大 0.25 WU 間隔、半径 0.675、設計上の身体高さ 1.6 で確認した。現在の対応 12 ポリラインは支持床・遮蔽物・身体干渉のサンプルエラー 0、接続成分 1、回転対応の不一致 0、上下の最小クリアランス 3.0、クリアランス違反 0。これはゲーム内の歩行試験ではない。

ゲームの実 Actor、人型とイカ、30/60/120 Hz、段差・坂端での接地、金網通過、弾・爆風、塗りセルと Turf 集計、カメラ、AI の上下ノード、オンライン同期、全ルールの生成・得点・移動物、短射程と長射程の対戦は未検証。幾何の回転対応は条件の対称性を示すだけで、勝率や武器間公平性の証明にはならない。元ゲームとの実機比較も未実施である。

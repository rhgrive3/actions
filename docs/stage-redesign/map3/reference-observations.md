# Splatoon 3 実ステージ視覚研究 — 通常公開2ステージの設計用

調査日: 2026-10-31 UTC。対象案件: rhgrive3/actions PR #1985 の Tidewater Plaza / Kelpline Terminal。これは設計判断の根拠を渡す調査メモであり、既存地形の置換・本番導入・ネイティブ移植ステージの変更を指示するものではない。

## 証拠の読み方と実施範囲

- **実画像を視認した**: ザトウマーケット、ヒラメが丘団地、マヒマヒリゾート＆スパ、コンブトラックの計4ステージ。Web検索で出典と版を特定した後、ブラウザで画像本体を開きスクリーンショットにより画素を確認した。検索ツールの `<<ImageDisplayed>>` 文字出力だけを視認扱いにしていない。
- **実動画は視聴していない**: 任天堂公式予告に由来すると画像ページが示す静止画を2点確認した。YouTubeページのメタデータ取得は映像視聴を意味しない。試合動画の移動時間・ジャンプ可否・復帰成功率を観測したとは主張しない。
- 俯瞰図はゲーム内の斜めの立体マップ表示であり、真上の正射影測量図ではない。画面内ピクセル面積、見かけの縦横比、陰影を公式床面積・メートル・WUへ変換しない。公式平均床面積、公式推奨幅、公式WU変換値は本調査から得られていない。
- ファイル履歴の日時は**画像アップロード日時**。撮影日時やゲームの厳密なビルド番号とは限らない。ファイル名・説明・掲載区分の版表示を採用した歴史資料であり、2026-10-31現在の全ルール版を保証しない。
- 通常ナワバリバトルの図を中心に揃えた。ガチエリア・ヤグラ・ホコ・アサリ・トリカラへ同じ地形接続や役割を一般化しない。
- 原画像をローカル保存するブラウザの共有ファイル同期を確認できなかった。画素はツールのスクリーンショットで実際に確認したが、ローカルに存在しない画像を成果物に同梱したとはしない。以下に再確認できるページURLと画像URLを記録する。

## ステージ別観察と設計推論

以下では「観察」を画面から直接読める形状、「推論」をその形状から考えられる対戦上の働きとして区別する。推論は実機で測定した勝率や支配範囲ではない。

### ザトウマーケット — 棚の端を使う平面選択

**観察 (V1)**: 外形は長軸を持つが、両端の陣地側では面が広がり、中央への接続付近で幅が変わる。中央に長い棚状の地形がずれて置かれ、側部にも通行余地がある。単に小箱を等間隔で散らした面ではなく、長い辺、短い切れ目、角、開けた部分が連続する。両陣地から中央へ向かう際、棚の内側と外側で曲がる位置・露出する方向が変わる。立体表示に段と斜面があるが、正確な高さ、全ての壁の塗り可否、ジャンプで越えられる辺は確定できない。

**推論**: 長い遮蔽物は視線を止めるだけでなく、端を回り込む決定点を作る。攻撃側は棚の一方を見せて別の端から圧力をかけられる設計を考えられる。防御側は単に中央を見るだけでなく、棚端が複数同時に開くことを警戒する必要が生じる。横移動を「広大な床を無遮蔽で横切る」動作にせず、遮蔽端と再合流面のセットで設計する教訓が得られる。

**限界**: この図だけから「独立した攻撃経路が正確に3本ある」「長射程から絶対安全」「棚上へどの側からでも登れる」と断言しない。

### ヒラメが丘団地 — 屋上・連絡床・低い路地

**観察 (V2/V3)**: 中央付近には横方向に連なる屋上状の床、細い接続面、カナアミ状の面があり、その手前・周囲に低い路地状空間が見える。端の陣地は中央と同じ高さ・同じ幅で一本につながる形ではない。中央の量塊が長い壁面を生み、細い足場と広めの屋上面を区別している。公式予告由来の斜め写真でも、建物上部と道路・橋状の床が異なる高さにあることを視認した。ただし写真は上空と背景の割合が大きく、下部が切れている。

**推論**: 高所から情報を得る価値と、足元や下部から接近される負担を組み合わせられる。平面上の複数ルートを単に横へ並べるだけではなく、同じ領域へ高さを変えて関与する設計が可能。攻撃は屋上確保、下路地からの接近、別の登り口への転進を役割として分けられる。防御高台には、正面監視の強さと、側方・背面の登り口を管理する責任を併せて与える。

**限界**: 地図の陰に隠れる床があるため、橋下の全接続、着地可能面、落下後にどの壁から戻れるかはこの写真だけで確定しない。V3は2022年の予告、V2は8.0表記なので、V3の細部をV2の現行詳細として扱わない。落下復帰は地形の印象ではなく、有向接続として別途実装検証する。

### マヒマヒリゾート＆スパ — 狭部・展開面・状態変化

**観察 (V4/V5/V6)**: 両端の広い陣地面から中央へ向かう部分は絞られ、中央の周囲に張り出しと離れた足場が見える。3.0と5.1では陣地の外形、中央周囲の横方向への張り出し、接続部の構成が異なる。5.1の方が中央周囲の足場と陣地出口を含め、選択できそうな場所が横方向に展開した構図になっている。5.1水位低下前後では中央付近の面表示と高低関係の見え方が変化する。

**推論**: 床を増やす場合、単に外周へ行き止まりを付け足すのではなく、戦闘に戻れる側面接続や展開面を作ると選択肢に結びつく。局所の足場は、飛び移る前の待機面と着地後の遮蔽があって初めて戦術的選択になる。攻撃側の分散が中央の圧力を変え、防御側には同じ一点を見続ける以外の対応が必要になる設計を考えられる。

**限界**: この3画像は倍率・角度が異なるため「床面積が何%増えた」とは測らない。暗い色をすべて水／穴、明るい色をすべて歩行可能床と決めつけない。水位変化による正確な床増加・経路切替・復帰可能性・発生時刻は今回の静止画観察では実測していない。Tidewaterへ水位ギミックそのものを輸入する必要はない。

### コンブトラック — 曲率と連続的な起伏

**観察 (V7/V8)**: 外形中央部が丸く膨らみ、両端に比較的直線的な陣地面が付く。中央には曲線状の輪郭と、外側を回り込む湾曲した通路が見える。公式予告由来の斜め写真では、中央の盛り上がり、波打つ走行面、カーブした壁、低い区画と高い区画を確認できる。これは同じ高さの台をいくつか置いた形ではない。

**推論**: 起伏を進むことで、見える相手・見られる範囲が連続的に変わる構成を作れる。中央を保持する側は周囲へ働きかけやすくても、斜面の裏と壁の曲がり角に死角を残せる。攻撃は山頂へ直行する以外に、外側を回って異なる向きから露出させる選択が成立するよう設計する。低所は必ず即死領域である必要がなく、情報や時間を失う代わりに再配置できる面として使える。

**限界**: 画像だけで正確な射線の開通角度や弾道を確認したわけではない。中央の暗部を通り抜けトンネルと断定しない。任意の低所が安全・全方向から容易に登れるとも保証しない。

## 共通して抽出できる設計原則

1. **外形が戦闘空間を説明する**。同じ長方形の中に違う名前の箱を入れるのではなく、張り出し、くびれ、斜め接続、湾曲、建物量塊でステージの読みを変える。広い床と狭い床は面積の帳尻ではなく、待機・接近・展開・退却の異なる役割を持つ。
2. **分岐の価値は再合流地点で決まる**。2本に分けても同じ狭い入口へ即座に戻るなら、防御側から見て一つの選択肢になりやすい。合流を前後または高さ方向にずらし、別角度から圧力を作る。ただし未検証の移動グラフを公式地図から確定しない。
3. **高さは床色の分類以上のもの**。段差、坂、屋上、橋、低路地、傾斜の頂点を用途に応じて使い分ける。上へ登る入口、下へ退く出口、落ちた後の再参加先を合わせて描く。縦に重なった床は一枚の俯瞰塗り面だけでは不足する。
4. **遮蔽は端の戦いを作る**。見えない面だけでなく、どこで身体を出すか、横へ移れるか、近距離が接近できるか、長射程がどこまで見通せるかを検査する。長い遮蔽と短い遮蔽、正面を遮る壁と足元を守る段を区別する。
5. **高所を占める利益と管理負担を対にする**。高台から全ての進入・出口・復帰面が同時に見える構成は避ける。高台への侵入は正面だけにせず、側方からの接近が高台側にも予測可能な形にする。
6. **落下を三種類に分ける**。死亡境界への落下、時間を失う回復可能な低所、短絡としての戦術的降下を別記する。この区分は提案であり、公式ステージ全域をこの分類で測定した結果ではない。
7. **変化を入れるなら状態ごとのグラフが必要**。動く床・水位・シャッターを加える前に、両状態でスポーンから交戦と退却へ到達できることを確かめる。今回の2案で静的地形だけで目標を満たせるなら、動的ギミックを追加する理由は薄い。

## 2つの独自ステージへの翻訳案

以下は参考作の写しではなく、新しいテーマ・接続・攻防役割に翻訳した提案。具体寸法はゲーム側の移動・跳躍・弾道能力から別途校正する。

### Tidewater Plaza: 折れた市場テラスと低い街路

- 核となる形: 折れた市場テラス、左右で向きの違う張り出し、低い街路。一直線の主通路ではなく、市場の広場へ段階的に視界が開く外形にする。
- 主戦場: 広い中央面を一枚の射撃場にせず、斜めの長い植栽基壇または水景の縁で二つの局所交戦面へ分ける。両面は遮蔽端で横移動できる。
- 高さ: 陣地の安全面、接近テラス、中央の低い盛り上がり、外周の低所を別の役割にする。一部に歩道橋と低路地の重なりを持たせる場合、下層が上層と異なる出口へ出ることを断面で示す。
- 攻撃: 正面の塗り圧、低い縁からの接近、短い高所からの支援を分担できる。防御: 中央を監視する高所に対して、斜めの遮蔽を使った接近が残る。
- 落下・復帰: 外周の一部に回復可能な低い受け面を設け、中央後方または側面へ戻る上りを付ける。即死の海側とは材質・縁の形・視認で区別する。水位変化は採用必須ではない。
- 独自性: コンブの丸い中央丘、ザトウの棚配置、マヒマヒの島配置をなぞらず、市場の連続したテラス・折れた縁・斜めの抜けを主役にする。

### Kelpline Terminal: 交差する貨物動線と上下の移動

- 核となる形: 細長さを残しつつ、平行な3本の廊下を避ける。ずれた荷捌き面、斜めの横断、くびれた連絡部、途中で広がる積み替え面を組み合わせる。
- 主戦場: 中央へ直行する地上動線、短い上部連絡橋、低い作業通路を異なる向きで交差させる。上部橋は全区間を見通せる長い狙撃線にせず、入口と出口が異なる遮蔽に守られる短い区間にする。
- 高さ: 始点の安全面→積み替えテラス→中央地上面→低い作業面に加え、局所的な上部橋を使う。「L0/L1/L2」の均一な3色に分けるだけでなく、連続坂と段を区別する。
- 攻撃: 表の大きい積み替え面を保持している味方が、下層の接近または側面の再合流を支える。防御: 上から中央を見ても低所の全区間は見えず、下層を止めるには位置を変える必要がある。
- 落下・復帰: 橋から作業面への降下を戦術的降下として扱い、戻り口を中央へ最短で直結させない。誤落下で同じ一点へ永久に閉じ込められないよう、味方側の安全な回復経路を残す。
- 独自性: ヒラメの屋上形状や既存港湾ステージの輪郭を写さず、「貨物動線が別の高さで交わる」構成を主体にする。ネイティブ移植対象はこの設計の変更対象に含めない。

## 次の設計で図と数値に落とす項目

| 検査 | 必須の表現 | 誤った合格の例 |
|---|---|---|
| 幅の変化 | 主要経路に沿う狭部・通常部・展開面の幅と、すれ違い/回避余地 | 最大幅だけ増やして途中の一本の喉が残る |
| 実際の選択肢 | 地形接続を有向グラフにし、分岐点と再合流点を記録 | 同じ射線上の同じ入口へ戻る道を独立経路として数える |
| 高さと重なり | 断面、上層/下層の分離俯瞰、接続方法、床・壁の塗り属性 | 俯瞰の床色だけで橋下の到達性を主張する |
| 射線と遮蔽 | 実装カメラ高さ・射出点・代表武器で主要守備位置を検査 | 遮蔽中心への直線一本で全キャラクターが隠れるとする |
| 落下と復帰 | 各縁に safe drop / recoverable / lethal、着地点、戻り口、露出区間 | 見た目の低所を全て回復可能とする |
| 攻防の入れ替わり | 中央未確保・中央確保・押し込まれた状態で役割を記述 | 中央確保時の有利さだけ見て打開経路を検査しない |
| 量の比較 | 外接矩形、重なりを一度だけ数える平面床、実際の上面床、壁面を区別 | 公式p表示をWU²へ無根拠に換算する |
| 動線と戦闘時間 | 実機移動速度で測った時間と、未校正の距離指標を区別 | 外形の縦横寸法だけで初動や復帰時間が同じと言う |

研究結論: 参考ステージの共通点を「三本レーン」「三段の高さ」「箱を置く」という部品に還元すると、今回求める独自性は弱くなる。まず異なる外形と交戦面を選び、幅の変化、遮蔽端、上下の重なり、再合流、回復可能な低所をその外形に結び付ける。最終的な公平性・武器適性・復帰性は、独自ゲームの移動と弾道の実装で検証する。

## MAP3実設計への適用境界

設計担当から共有されたTidewaterの水平床高 0 / 1.2 / 2.4 / 3.6 / 4.8 WU と、上部ホール下の街路に対する4.2 WUクリアランスは、**独自ゲームの設計値**である。本調査が任天堂の地形から読み取った寸法ではない。五つの高さを設けること自体を合格理由にせず、東側の横断方向の登り・降り、上部ホールと低街路の別々の出口、低所からの再参加が用途の違いとして成立するかを確認する。Kelplineの相互に入り組むターミナル島は、マヒマヒの島配置を複製するのでなく、端部での分岐・異なる方向での再合流・落下後の再参加を独自に構成する対象として参照する。

ネイティブ地形監査の面積値と本調査の画像観察は独立した証拠である。ネイティブ面積を引用する場合は担当監査の算出方法と元データを参照し、ここで公式面積の裏づけとして扱わない。
